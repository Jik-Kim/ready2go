# ROKEY 웹 대시보드

> [문서] 이 폴더는 이슈 [#112](https://github.com/Jik-Kim/ready2go/issues/112)의 PC·모바일 웹 UI 제안을 검토하기 위한 정적 데모입니다. 현재 실제 음성·Runner·ROS 2·MongoDB·로봇과 연결되어 있지 않으며, P3 또는 `AC-DEMO-01` 완료를 뜻하지 않습니다.

## 1. 이슈 #112에서 웹 UI가 바뀐 과정

이 화면은 처음부터 지금 모습으로 만들어진 것이 아닙니다. 이슈 #112에서 목업과 표시 항목을 검토하면서 다음 순서로 바뀌었습니다.

1. **최초 제안** — PC·모바일에서 같은 작업 상태를 보고, 음성·로봇·카메라 상태와 서랍·준비물·현재 작업을 표시하는 구성을 제안했습니다.
2. **두 번째 목업** — [댓글 6033300834](https://github.com/Jik-Kim/ready2go/issues/112#issuecomment-6033300834)에서 연결 상태를 작은 블록으로 줄이고, 임시 트레이·별도 복구 영역·이벤트 기록을 제거했습니다. 모바일에는 명령 상세와 서랍 보기를 분리했습니다.
3. **최신 작업 상세 목업** — [댓글 6037139561](https://github.com/Jik-Kim/ready2go/issues/112#issuecomment-6037139561)에서 명령 접수 배지를 작업 상세 안으로 옮기고, 현재 동작 옆에 `작업 상세 보기 ▾`를 배치했습니다. 실행 단계는 접이식 가로 진행 형태로 변경하고 작업 중단 버튼은 오른쪽에 두었습니다.
4. **현재 구현** — 최신 목업을 기존 정적 UI에 반영했습니다. `1 / 3 전달 완료`, `결과 확인 중`, 데이터 기반 단계 순서, 모바일 내부 가로 스크롤, 선택 서랍과 실제 작업 위치의 분리를 확인할 수 있습니다.

목업의 물품·시각·실행 순서는 예시입니다. 실제 연동 후에는 서버가 제공한 데이터와 단계만 표시해야 합니다.

## 2. 파일 역할

| 파일 | 역할 | 수정하는 경우 |
|---|---|---|
| `index.html` | 화면의 HTML 구조와 CSS·JavaScript 진입점 | 화면 영역을 추가·제거하거나 접근성 구조를 바꿀 때 |
| `styles.css` | 색상, 크기, PC·모바일 배치, 서랍 모양, 가로 진행 단계 | 목업의 시각 배치나 반응형 기준을 바꿀 때 |
| `demo-data.js` | 현재 정적 시연에서만 쓰는 샘플 상태 | 데모 물품·연결 오류·빈 목록 등 샘플 시나리오를 바꿀 때 |
| `app.js` | 데이터를 HTML에 표시하고 서랍 선택·상세 토글·패널·데모 중단을 처리 | 렌더링 규칙이나 사용자 상호작용을 바꿀 때 |
| `README.md` | 변화 과정, 실행·접속·실제 연동 교체 지점 설명 | 웹 UI의 사용법이나 연동 방식이 바뀔 때 |

파일 연결 순서는 다음과 같습니다.

```text
index.html
 ├─ styles.css      화면 모양과 반응형 배치
 ├─ demo-data.js    데모 전용 상태 데이터
 └─ app.js          데이터 표시와 버튼 동작
```

## 3. 현재 데이터와 이벤트 구조

`app.js`는 `demo-data.js`가 제공하는 `window.ROKEY_DEMO_DATA`를 읽습니다.

| 화면 | 현재 데이터 경로 |
|---|---|
| 장치 연결 | `connections[].status`, `statusLabel`, `description` |
| 음성 호출 인식 | 음성 연결 항목의 `callStatus`, `callStatusLabel` |
| 들은 말·해석·접수 | `command.heard`, `understood`, `recognition`, `interpretation`, `receipt` |
| 선택한 서랍 | `selectedDrawerId` |
| 실제 작업 위치 | `task.workDrawerId` |
| 등록 물품 | `drawers[].items` |
| 준비물과 완료 수 | `supplies[]`; `status === "delivered"`만 완료로 계산 |
| 현재 작업과 단계 | `task.currentAction`, `currentItemIcon`, `steps[]` |

현재 사용자 이벤트는 다음과 같습니다.

- 서랍 선택: `selectDrawer()`가 조회 대상만 바꾸며 로봇 명령을 보내지 않습니다.
- 작업 상세: `toggleTaskDetails()`가 화면의 상세 영역만 열고 닫습니다.
- 명령·서랍 모바일 패널: `openDialog()`와 `closeDialog()`가 열기·닫기 및 포커스 복귀를 처리합니다.
- 작업 중단: `stopDemoTask()`가 로컬 샘플 상태만 바꿉니다. 실제 중단 API 호출은 없습니다.

## 4. 실제 서버와 연동할 때 교체할 곳

HTML에서 MongoDB나 ROS 2에 직접 연결하지 않습니다. Runner 또는 별도 웹 API 서버가 상태를 정리해 웹에 전달해야 합니다.

### 4.1 상태 데이터

가장 작은 교체 방법은 다음과 같습니다.

1. `index.html`의 `<script src="./demo-data.js">`를 실제 웹 API 어댑터 파일로 교체합니다.
2. 어댑터는 서버 응답을 위 표와 같은 화면 데이터 형태로 정규화합니다.
3. `app.js` 처음의 `const state = window.ROKEY_DEMO_DATA;`를 어댑터가 제공하는 값으로 교체합니다.
4. 갱신 방식이 polling, SSE 또는 WebSocket으로 확정되면 새 상태를 받은 뒤 기존 `renderConnections()`·`renderCommand()`·`renderInventory()`·`renderSupplies()`·`renderTask()`를 다시 호출합니다.

다음 원칙은 유지합니다.

- `connections[].status`는 실시간 연결 자료로만 채웁니다. 저장 이력이 있다는 이유로 연결됨을 표시하지 않습니다.
- 음성 장치 연결과 호출 인식은 별도 필드로 유지합니다.
- 선택 서랍은 UI 조회 상태이며 `task.workDrawerId`를 바꾸거나 서랍 개방 명령을 만들지 않습니다.
- Runner가 단계 정보를 주지 않으면 임의 단계를 생성하지 않고 `확인 전`으로 표시합니다.
- `verifying`·`결과 확인 중`은 전달 완료 수에 포함하지 않습니다.

### 4.2 작업 중단

실제 중단 경로가 합의되면 `app.js`의 `stopDemoTask()`를 교체합니다.

1. 버튼 클릭 시 기존 웹 서버의 중단 요청 API를 호출합니다.
2. 응답을 `요청 중`·`처리 완료`·`실패`로 구분합니다.
3. 요청 성공 응답만으로 물리적 정지나 안전 복구 완료를 단정하지 않습니다.
4. 물리적 E-stop, Runner의 `finally` 복구, 기존 로그 저장 코드는 변경하지 않습니다.

API URL·인증·요청/응답 형식과 상태 갱신 방식은 아직 정해지지 않았습니다. 이 값들은 이슈 #112에서 C·E 담당과 확정해야 합니다.

## 5. 웹페이지 실행

프로젝트 PC에서 `ready2go` 저장소 루트로 이동한 뒤 다음 명령을 실행합니다.

```bash
python3 -m http.server 4173 --directory web
```

이 명령은 파일을 보여 주는 임시 정적 서버이며 별도 Python 애플리케이션을 만드는 것이 아닙니다. 터미널을 닫거나 `Ctrl+C`를 누르면 서버가 종료됩니다.

같은 PC에서는 다음 주소로 접속합니다.

```text
http://localhost:4173
```

## 6. 휴대폰과 다른 PC에서 접속

### 6.1 서버 PC의 주소 확인

서버를 실행한 PC에서 새 터미널을 열고 다음 명령을 실행합니다.

```bash
hostname -I
```

여러 주소가 나오면 보통 와이파이·유선 LAN 주소를 사용합니다. `172.17.x.x`처럼 Docker가 만든 주소는 사용하지 않습니다. 현재 확인된 서버 PC 주소 예시는 `172.24.1.176`입니다.

### 6.2 휴대폰

휴대폰을 서버 PC와 같은 와이파이에 연결하고 브라우저에서 다음 형식으로 접속합니다.

```text
http://서버_PC_IP:4173
```

현재 확인된 예시는 다음과 같습니다.

```text
http://172.24.1.176:4173
```

화면 폭에 따라 모바일 배치로 자동 전환되며 별도의 `/mobile` 주소는 없습니다.

### 6.3 다른 PC

다른 PC도 서버 PC와 같은 네트워크에 연결한 뒤 같은 주소를 사용합니다.

```text
http://172.24.1.176:4173
```

접속되지 않으면 다음을 확인합니다.

- 서버 PC 터미널에 `Serving HTTP on 0.0.0.0 port 4173`이 표시되는지
- 두 장치가 같은 와이파이·유선망에 있는지
- 방문자망·기관망에서 장치 간 통신을 차단하지 않는지
- 서버 PC 방화벽이 TCP 4173 포트를 차단하지 않는지

## 7. 테스트용 데모 시나리오

화면 버튼을 추가하지 않고 URL로 예외 상태를 확인할 수 있습니다.

```text
http://localhost:4173/?scenario=long
http://localhost:4173/?scenario=empty
http://localhost:4173/?scenario=error
```

각각 긴 물품명, 빈 목록, 연결 오류의 화면 넘침을 확인하기 위한 데모입니다.
