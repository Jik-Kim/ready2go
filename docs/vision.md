## 9. 비전 파이프라인 상세 (담당 A, 핵심 경로)

| 단계 | 내용 | 완료 시점 |
| :--- | :--- | :--- |
| **V0 카메라·캘리브레이션** | 손목 RealSense 컨테이너, 표준 토픽 remap. 강의 `Calibration_Tutorial`로 **핸드-아이 캘리브레이션**(`T_gripper2camera`) 재수행, 서랍 좌표계와 함께 TF 발행 | Day 2 |
| **V1 실물 데이터셋** | 로봇을 `drawer_top_view` 포즈에 두고 물품 배치·겹침·조명을 바꿔 가며 촬영(클래스당 150~300장). 사전 라벨링(YOLO-World 등, **SAM2 마스크 → 박스 변환으로 보조**) 후 수동 보정. 오프라인 작업(PC1). 도구·절차: [`tools/yolo/README.md`](../tools/yolo/README.md) | Day 3~4 |
| **V2 YOLO + Depth** | YOLO(v8n/s) 검출 → 뎁스로 3D 위치 → 서랍 좌표 변환 → **yaw 산출**(서랍 바닥 위 뎁스 덩어리 윤곽의 긴 변 방향 `minAreaRect`, 대칭 물체는 0 고정, 비교 실험은 #62·#63) → `top_z` 내림차순 정렬. 학습·평가 도구: [`tools/yolo/README.md`](../tools/yolo/README.md) | Day 5~6 |
| **V3 미지 물체 · ID 추적** | 서랍 바닥 평면 위 뎁스 덩어리 중 검출되지 않은 것을 `unknown#n`으로 생성(클래스 무관). 재촬영 간 ID는 서랍 좌표 최근접 매칭(3cm 이내 + 같은 클래스)으로 유지. (조건부) Day 6에 뎁스 덩어리 방식이 정확도 기준(위치 1.5cm, 가림 순서 90%)에 못 미치면 덩어리를 SAM2 점·박스 프롬프트로 넘겨 마스크 정밀화(`VISION_MODE=yolo_sam2`, 출력 형식 동일) | Day 6~7 |
| **V-sim (보조)** | Isaac Sim 손목 카메라 + **oracle(시뮬레이터 정답)** 으로 `inspect_region`과 동일 형식 출력 → 사전 검증 모드 전용 | Day 4 (트윈 일정 내) |

* **모델 결정**: 학습 중인 `Fruits/best.pt`는 서랍 물품과 클래스가 달라 사용하지 않음. **실물 데이터로 학습**하고, Isaac Sim Replicator 합성 데이터는 여유 시 보강용으로만 사용.
* **pose 산출 (V2)**: `position`은 YOLO 박스 중심, `position.z`는 0, `yaw`는 긴 변 방향 (−π/2, π/2] — 정의 원본은 [runner.md 7.1](runner.md). 아래는 아직 정해지지 않은 부분이다.
  * **yaw 산출 방식 (P1 기준선, 사용자 확정 10/04)**: YOLO 박스 안에서 서랍 바닥보다 높은 뎁스 픽셀을 덩어리로 분리하고, 그 윤곽의 최소 외접 사각형(`cv2.minAreaRect`) 긴 변 방향을 yaw로 쓴다. 대칭 물체는 0 고정. 같은 덩어리에서 `top_z`(덩어리의 최고 높이)도 구하며, V3 미지 물체의 "뎁스 덩어리"와 같은 분리 단계를 재사용한다. 비교 실험은 데모 경로 밖으로 분리: YOLO-OBB([#62](https://github.com/Jik-Kim/ready2go/issues/62), 조장 E 합의 후 착수), SAM2 마스크([#63](https://github.com/Jik-Kim/ready2go/issues/63), FR-VIS-04, P3 선택).
  * **구조 제안 (구현은 Day 5 `inspect_region` 실제 구현 PR)**: `ready2go_vision/core/`에 yaw 추정기 인터페이스(입력: 박스·컬러·뎁스, 출력: yaw·신뢰도)를 두고 뎁스 덩어리를 기본 구현으로 한다. OBB·SAM2는 같은 인터페이스에 붙이며 `VISION_MODE`로 선택(기본 = 뎁스 덩어리). 덩어리가 작거나 비정상(뎁스 결손, 너무 얇음)이면 yaw 0 + 낮은 신뢰도로 폴백하고, 판정 임계값은 코드에 하드코딩하지 않고 params(yaml)에 `[팀 확정 필요]`로 둔다.
  * **정답 yaw 기록 `[팀 확정 필요]`**: 비교 실험이 공정하려면 같은 이미지에 정답 yaw가 필요하다. 촬영 때 기록하는 방법(각도 지그 또는 격자 시트)은 #62에서 정한다. 자리표시로 `capture_session.py --gt-yaw-method`가 `session.yaml`에 방법을 남긴다.
  * **대칭 물체 판정 `[팀 확정 필요]`**: 원통·정사각형은 yaw 0 고정인데 온톨로지에 형상·대칭 속성이 없다(`size_m`만 있음). 후보: 긴 변/짧은 변 비 < 1.2, 또는 온톨로지 `yaw_free` 플래그(계약 변경, #46과 겹치니 E와 조율).
  * **투영 높이 평면 `[팀 확정 필요]`**: 박스 중심 픽셀을 서랍 좌표 x·y로 옮길 때 어느 높이(바닥 z=0 / `top_z`/2 / 윗면)의 평면과 교차시킬지. 카메라가 비스듬하면 높이만큼 오프셋이 생겨 AC-VIS-01(1.5 cm)에 영향을 준다.
  * **머리 방향(망치·스패너·당근 펜)**: P1에서는 제공하지 않는다. B의 파지 시험에서 필요하다고 하면 `result_json` 확장(계약 변경)으로 별도 요청한다.
* **서랍 높이**: 새 서랍은 처짐이 없다(`config/places.yaml`의 `sag_m_at_max_travel` = 0 [실측 A 10/03]). 그래도 얇은 물품은 뎁스 오차 몇 mm로 물체와 바닥이 구분되지 않을 수 있으므로 높이는 서랍 바닥 기준(힘 감지, [domain.md 8.5](domain.md))으로 잡고 비전은 x·y를 쓴다.
* **실물 특유 리스크**: 반사·검정·투명 물체의 뎁스 결손, 조명 변화, 서랍 내부 그림자 → 물품 선정 기준(2.3), 무광 서랍장(2.2), 조명 고정으로 대응.
* **학습 통과 기준**: 학습에 쓰지 않은 촬영 세션 검증셋에서 mAP50 0.9 이상 `[팀 확정 필요]`(이슈 #14 제안값). 최종 합격은 [requirements.md](requirements.md#ac-vis-01)의 AC-VIS-01(3D 위치 오차 1.5cm)·AC-VIS-02(가림 순서 90%)이며, mAP50은 그 전 단계의 모델 점검 기준이다.
* **평가**: 실측(자·격자 시트) 대비 3D 위치 오차, 검출 정밀도·재현율, 가림 순서 정확도.
