# Ready2Go 요구사항 기준 문서

> **문서 역할:** 프로젝트 목표, 범위, 기능·비기능 요구사항, Phase 진입·완료 기준의 단일 기준 원본(Single Source of Truth).
> P1·P2·P3 모두 의미·정의·정책·책임 경계·Phase·수용 기준을 이 문서에서만 정의한다. 다른 문서는 해당 FR/NFR/AC 앵커를 링크로 참조하며 자기 모듈의 현재 구현·운용·시험 방법·실측 결과를 기록한다. 기준을 복사하거나 예시로 정책을 변경하지 않는다. 실행 필드·타입·enum·설정값은 기존 JSON/YAML 원본을 참조한다.
> 관련 문서: [문서 인덱스](README.md) · [시연 시나리오](demo_scenario.md)

## 1. BRD — 비즈니스 요구사항

### 1.1 목표

1. **음성 기반 물품 탐색·전달:** 한국어 음성 명령을 받아 서랍 안의 지정 물품을 찾아 전달 트레이에 놓는 협동로봇 시스템을 구현한다.
2. **온톨로지 기반 스킬 조합:** 작업 공간, 물품, 로봇 상태, 스킬의 조건과 결과를 온톨로지로 표현하고, 플래너가 목표 달성을 위한 실행 순서를 생성한다.
3. **가림 물체 탐색·복구:** 목표가 가려진 경우 장애물을 같은 서랍 내부 빈 공간으로 옮겨 재관측하고, 목표 전달 후 이동한 물체를 역순으로 복구한다.
4. **수업 기술 통합:** ROS 2 Jazzy, RealSense와 카메라 보정, YOLO 학습·추론, 음성 처리, Doosan M0609, OnRobot RG2·Modbus, Docker, 다중 PC 통신, 데이터베이스를 연동한다.
5. **단계적 개발:** 실물 기본 탐색부터 완성하고, 동적 플래닝·가림 처리·다중 서랍 탐색으로 확장한다. 시뮬레이션과 mock은 개발·사전 검증에 사용하며 실물 안전 절차를 대체하지 않는다.

## 2. Phase 범위

Phase는 기능 단위이며 순서대로 누적한다. Phase 1만으로도 음성·비전·실물 Pick and Place·Docker·DB 등 수업 필수 스택이 동작해야 한다. **온톨로지 조건·결과에서 플래너가 스킬 순서를 도출하는 장면은 Phase 2의 필수 완료 기준**이다.

- Phase 1만 완성되어도 강사 챌린지 3요소(동작·상태 JSON, JSON 조합, 성공 여부 로그)를 최소 충족한다. 일정이 밀려도 프로젝트가 성립하도록 하기 위함이다.
- 다음 Phase 기능은 이전 Phase 완료 기준을 통과한 뒤 착수한다. 단, 데이터 수집·트윈 씬 구성 등 다음 Phase의 선행 작업은 병행할 수 있다.

Phase 배정을 바꿀 때는 아래 FR/NFR 표를 먼저 수정하고, 관련 주제 문서의 요구사항 ID 링크와 필요한 작업 요약을 **같은 PR에서** 확인·갱신한다. 주제 문서의 안내는 이 문서의 기준을 복제하지 않으며, 관련 ID를 가리킨다.

|---|---|---|---|
| **Phase 1 — 기본 음성 Pick and Place** | 음성·키워드 추출, 기본 온톨로지와 선언형 태스크 실행, RealSense 보정·YOLO, Doosan/RG2 제어, MongoDB 로그, Docker와 다중 PC 통신 | “헬로 로키, 지우개 찾아줘” → 위 서랍 열기 → 보이는 지우개 집기 → 전달 트레이에 놓기 → 서랍 닫기 → 홈 복귀. 실패·취소 시 [NFR-SAF-02](#nfr-saf-02)의 안전 조건을 따르며 정지/잠금 또는 그리퍼 상태가 불명확한 경우 자동 닫기·홈 이동을 보장하지 않는다([문서: 쥔 채 정지 #82](https://github.com/Jik-Kim/ready2go/pull/82)·[안전 정지 후 finally 동작 억제 #74](https://github.com/Jik-Kim/ready2go/pull/74)). 스텝별 결과를 MongoDB에 저장한다. | [FR-INT-01–03](#fr-int-01), [FR-ONT-01](#fr-ont-01), [FR-PLN-01](#fr-pln-01), [FR-VIS-01–02](#fr-vis-01), [FR-ML-01](#fr-ml-01), [FR-ACT-01–03](#fr-act-01), [FR-LOG-01](#fr-log-01), [FR-COM-01–02](#fr-com-01), [NFR-ENV-01](#nfr-env-01), [NFR-DB-01](#nfr-db-01), [NFR-SAF-01–02](#nfr-saf-01) |

[문서] P2 안전 목표·완료 기준은 아래 FR-SAF-01–03·AC-SAF-02–04를 따릅니다. 담당별 진행 상태·일정·합의값 반영 여부는 [#153](https://github.com/Jik-Kim/ready2go/issues/153)에서 관리합니다. 요구사항 목표는 운영 연결·계약 승인·실물 검증 완료를 뜻하지 않습니다.

## 3. 기능 요구사항

검증 방법은 각 Phase 완료 시 실제 결과를 확인할 기본 방법이다. 실물 조작은 [safety.md](safety.md)의 절차를 따른다.

|---|---|---|---|
| <a id="fr-int-01"></a>FR-INT-01 | 음성 명령 입력 | 웨이크워드 이후 한국어 음성을 STT 텍스트로 변환한다. CLI/텍스트 입력은 디버깅용 보조 경로로만 제공한다. 웨이크워드·STT가 포함된 실시간 음성 명령으로 UC-P1을 시작해 확인한다. | P1 |

[place 중 놓침의 새 실행 예외](#halt-motion-policy)는 별도 경로로 처리한다. 재전송 전 부분 동작·effect 중복 방지 검사를 통과해야 한다. 무응답·거절·재정지·과거/중복 응답은 차단한다. 부분 실행된 원자 동작/params/궤적을 무조건 재전송하거나 effect를 완료 처리하지 않으며 자동 재개를 금지한다. | P2 |

| <a id="fr-ont-02"></a>FR-ONT-02 | 온톨로지 상태 추적 | P1의 실행 응답 기반 상태 갱신을 확장한다. 실행 응답만으로 성공을 단정하지 않고, `verify` 사후 관측이 통과한 경우에만 효과를 상태에 반영한다. | P2 |
| <a id="fr-ont-03"></a>FR-ONT-03 | 클래스 추론·정합성 검사 | 클래스 계층과 개체 관계를 사용한 목록·분류 조회를 제공한다. 상충하거나 누락된 참조를 검사하고 결과를 기록한다. | P3 |
| <a id="fr-pln-01"></a>FR-PLN-01 | 선언형 태스크 실행기 | JSON 태스크의 `sequence`, `if`, `retry`, `timeout_sec`, `finally`를 실행한다. 스킬 실행 전에 온톨로지 `pre` 조건을 확인하고, 불충족이면 실행하지 않고 오류 코드를 남긴다. 스킬이 성공을 반환하면 `effect`로 상태를 갱신한다. 제어 흐름은 데이터로 정의하고, mock 환경에서 정상·실패 경로를 확인한다. | P1 |

### 3.1 물품·상태 의미 정책 — FR-ONT-01–03 / FR-INT-02

[문서: 기존 #8·#6·#61 합의] P1은 등록 물품의 단일 요청이며 시연 예시·초기 배치·목록 데이터로 요청 범위를 제한하지 않는다. 목록·분류는 P3이다. 물품 분류와 역할은 별개이며 장애물 역할도 요청을 금지하지 않는다. 등록·인식·라벨링은 파지 승인과 구분한다. 일반 높이 선정 기준은 1.5 cm 이상을 유지하고 지우개만 예외이며, 개별 시험 결과를 모든 배치의 승인으로 확대하지 않는다([#8 결정](https://github.com/Jik-Kim/ready2go/issues/8#issuecomment-5980582810)).

물품 키·온톨로지 분류·관측 인스턴스 ID를 구분한다. `size_m`은 눕힌 물체 로컬 x 긴 변·y 짧은 변·z 높이의 외접 박스(m)이며 파지점·손잡이 폭을 뜻하지 않는다. 실제 위치와 초기 상태 예시는 구분한다. 현재 상태 적용·저장은 Runner(C), 지식 로딩·조건/효과 함수는 E 책임이다. 미측정·미승인 설정은 임의 기본값으로 채우지 않으며, 실행 경로 연결과 차단 여부는 담당 코드에서 별도로 확인한다.

### 관측 좌표의 의미 — FR-VIS-01–03 / FR-ONT-01

[문서: #6·#61·#69 기존 합의] `pose`의 x·y는 관측 박스 중심의 서랍 좌표이며 z 자리표시와 물체 높이를 구분한다. yaw는 긴 변 방향, 위에서 본 모양이 정사각형/둥근 대칭 물체는 0이다. `yaw_valid=false`의 0은 실제 방향 확정값이 아니다. 투영 평면과 구체 수치·프레임은 [places 원본](../config/places.yaml)·[관측 예시](../contracts/examples/inspect_region_result.json) 및 A 규칙 구현에서 확인한다. 서랍 관측의 `top_z`는 해당 서랍 좌표계 바닥(z=0) 기준 물체 윗면 높이이며, 다른 물체 위에 얹혔으면 아래 물체 높이를 포함한다. 다른 관측 영역의 높이 기준은 `pose.frame`과 해당 실행 원본을 확인하며 모든 영역을 서랍 좌표계로 강제하지 않는다. `top_z`를 항상 물품 명목 높이로 대체하지 않는다. 클래스 키를 관측 인스턴스 ID로 임의 변환하지 않으며 촬영 내 ID와 지속 추적 ID를 구분한다. 미발견과 통신/관측 실패, 예상 위치·명령 위치·재관측 실제 위치는 서로 다른 증빙이다.

### 3.2 음성 해석·평가 정책 — FR-INT-01–03 / AC-INT-01–03

[문서: 사용자 승인 E-VOICE-UX-20261009-01] P1은 등록 이름/별칭으로 확인된 단일 물품 받기·가져오기 요청을 수용한다. 이름+“좀/좀요”는 축약 부탁이다. “망치 가져오라고 말했잖아”, “엄마가 망치 가져오라고 했어”처럼 실제 전달 요청의 인용·전언도 수용하되 표면 문자열만으로 허용하지 않는다. 부정·제외·번역/문장 설명·정보 질의·다중 대상·불명확 문맥·미지원 행동/목적지는 실행 후보로 확정하지 않는다. 건네기는 전달 트레이 흐름이며 직접 손 전달·반납·정리·던지기는 제외한다. 가능 여부 질문은 등록/해석 지원을 안내하며 실행하지 않고, Runner 지원·실재고·파지 가능을 확인 전으로 구분한다.

대상 단독·대명사·대상불명은 유효한 현재 확인 질문이 없으면 clarify/빈 targets로 보류한다. 현재 질문·후보 대상·판정·세대·유효성을 보존해 명확한 응답과 대상 정정을 결합한다. 취소·새 독립 요청·만료·재시작·실행 중/잠금·경고로 문맥을 무효화한다. 질문당 최종 후보/발행은 한 번이며 TTS 실패·발행 예외 후 자동 재시도하지 않고 새 독립 요청을 요구한다. 일반 질문 시간 설정은 제안/미확정으로 원본에서 관리하고 P2 사건/10초 정책을 전용하지 않는다.

정상 LLM 후보에는 계약·허용값·등록 단일 대상·발화/현재 질문 대상 일치·유한 확신도·요청 의미를 확인한다. 오류·시간 초과·검증 실패/LLM 없음에는 좁은 규칙 폴백만 사용한다. 내부 원본 응답 후보와 공개 clarify_question, 검증된 최종 안내, 발행 intent를 분리한다. 대상·행동·판정에 일치하는 유효 문장은 일반 고정문구로 덮지 않고 터미널과 TTS에 동일하게 전달한다. 미등록 물품과 unknown 요청 안내를 구분하며 실행 약속·완료 확답은 현재 판정과 모순되면 대체하고 사유를 기록한다. TTS 확인 실패 시 find_item 발행 차단과 평가 모드 전체 발행 차단을 유지한다. publish 성공은 C 수락/실행 시작/완료가 아니며 요청 상관 근거와 수락 안내 연결은 C 협의 전 미연결이다.

초기 필수 안내와 자주 사용된 검증 문장의 bounded 선준비를 구분한다. 현재 모델/음성/내용 identity의 합성 후 디스크 저장·재사용을 유지하고 과거 질문 권한을 복원하지 않는다. 문장수·길이·용량·준비 실패/진행은 실행 원본 설정으로 관리하며 캐시 때문에 최종 문장을 바꾸지 않는다. 콘솔은 최종 안내·대상·발행/수락 구분·보류/오류 중심, E 로컬 상세 파일은 민감정보를 제거한 원본 LLM·검증 사유·원본/최종 문장·TTS/캐시/단계시각·로컬 요청/질문 연결을 보존한다. 파일 실패는 경고하고 음성·취소를 막지 않는다. C 실행 DB/상태·worker JSON pipe는 별도 책임이다. 무음 종료는 비교 검토이며 검증 없이 녹음 기본값/임계값을 바꾸지 않는다.

평가 문장은 허용 발화 목록·학습 자료가 아니며 텍스트 override·모의 API는 실제 웨이크/STT 평가를 대체하지 않는다. E/D 구성안(요청20/모호10/미등록·미지원10)은 미확정 시험 설계이며 문장별 정답표·자료 승인은 별도이다. 전체 표본·화자·자유 표현·수치는 [AC-INT-01](#ac-int-01), 실패/잘못된 실행은 [AC-INT-02](#ac-int-02), 응답 지연은 [AC-INT-03](#ac-int-03)에만 정의한다. 평가 모드는 모든 intent 발행을 차단한다. 런타임 모드·장치·엔진·시간 상한은 아래 실행 원본을 확인한다.

[문서: #150 승인 선정 목표·1단계 내부 평가] P2 구조화 목표 추출은 [FR-INT-02](#fr-int-02)에 따른다. 선정 목표의 물품·목적지·열림 값은 [voice.yaml의 p2_goal_catalog](../ros2_ws/src/ready2go_voice/params/voice.yaml)이 실행 원본이다. 명시된 최종 열림을 자동 닫힘으로 바꾸지 않으며 발화와 선정 목록·현재 등록 온톨로지가 일치하는 목표만 후보로 수용한다. 부정·충돌·불명확·범위 밖·LLM 실패는 실행 후보를 확정하지 않는다. 기본 P1 경로를 유지하며 옵트인 상태에서도 이번 단계는 내부 평가와 안내만 허용하고 운영 발행을 차단한다. 초기 관측 상태나 행동 순서를 LLM이 만들어 실행하지 않는다. 실물 파지 승인·[FR-PLN-02](#fr-pln-02)의 계획·[FR-ONT-02](#fr-ont-02)의 검증/효과·[AC-PLN-01](#ac-pln-01)의 실물 기록은 후속 조건이며 목록 등록이나 내부 후보 출력으로 완료를 선언하지 않는다.

P2 실행 모델은 yolo11s-seg 단일 경로, OBB는 보류, SAM 실행은 [FR-VIS-04](#fr-vis-04)의 P3 선택이다. 라벨링 보조 도구와 런타임 모델은 구분한다. 첫 P2 시연에서는 한 배치에 각 클래스의 물체를 1개씩 배치하며, 동일 클래스 복수 물체는 후속 P2 검증으로 남긴다. 실제 물리 배치 확정·실물 완료는 별도이다.

[합의: #169 사용자 결정] `visible_area_m2` 채택과 관계 우선 사용은 [E 사용자 결정 전달](https://github.com/Jik-Kim/ready2go/pull/169#issuecomment-6053079226)을 근거로 한다. `occluded_by`의 직접 가림 방향관계가 제거 순서의 선행 제약이다. 그 제약을 만족한 제거 가능 후보끼리만 `visible_area_m2`(현재 보이는 마스크의 물리 면적)를 우선순위로 사용한다. 전체 면적·가림 비율로 해석하거나 덮인 물체를 면적만으로 먼저 집지 않는다. 파지·놓기 안전 판단은 B가 동작 직전에 수행한다. 가림 판정은 A의 segmentation·depth·국소 경계 높이에 기반하며 전역 `top_z` 큰 순서를 위아래 정답으로 단정하지 않는다. 명목 높이 비교는 보조 검사이며 모든 형상의 필수충분조건이 아니다. 순환·null·미검출·모호한 관계는 정상 관계나 안전 후보로 확정하지 않는다. 구체 필드 형식·누락 처리·예시는 기존 계약 원본을 대조하며 승인되지 않은 확장은 확정 계약으로 취급하지 않는다.

이동 후 재촬영한 현재 좌표로 실행하며 C가 재식별한다. 클래스와 원래 위치·명령한 놓기 위치·실제 관측 위치를 분리한다. 유의미하게 옮긴 물체는 같은 Unpacking에서 반복 제거 후보에서 제외하며 영구 금지가 아니다. 모호하면 동일 물체로 확정하지 않는다. LIFO 복구는 원래 서랍 로컬 pose와 현재 관측·지지면을 대조한다. 복구 목표의 지지면은 바닥 또는 아래 물체 윗면이다. 개별 백엔드의 지원 범위를 전체 완료 목표로 축소 합의한 것으로 보지 않는다. 구현 지원 상태·협의 진행은 담당 CURRENT와 기술 문서에 기록한다.

[AC-VIS-02](#ac-vis-02)는 GT의 **직접 가림 방향관계**만 대조하며 추이 관계를 섞지 않는다. TP는 GT 방향까지 일치한 관계, FN은 GT 관계 누락·관계 null·물체 미검출로 확인하지 못한 관계, FP는 GT에 없거나 반대 방향인 관계이다. 방향 반전은 FP와 FN 모두에 센다. 유효 분모에서 `recall = TP/(TP+FN)`, `precision = TP/(TP+FP)`를 사용한다. 비전 장면 성공은 GT 직접 가림 방향관계를 누락·헛관계 없이 전부 맞힌 경우이다. 올바른 제거 순서와 실제 Unpacking 성공은 [FR-ACT-04](#fr-act-04)·[AC-ACT-02](#ac-act-02)의 통합 검증으로 별도 기록한다. 임계값 조정에 쓴 장면으로 AC-VIS-02 합격을 판정하지 않으며 평가 GT 장면은 별도로 촬영한다. GT 관계 0인 장면의 recall 또는 예측 0인 precision은 분모 0을 임의 성공/실패 숫자로 채우지 않는다. 유효 분모·비가림 대조 시험을 별도 기록하고 분모 0 집계 방식은 `[팀 확정 필요]`로 남긴다. 보조 지표와 모름/미검출을 함께 기록한다. 위·아래 고정 배치 장면 시험은 [AC-ACT-02](#ac-act-02)의 무작위 배치 탐색 시험을 대체하지 않는다.

[사용자 결정: #43] pick은 같은 pick의 폭 축소 grip가 정상 완료된 뒤 유효한 실측 폭을 검증한다. 망치 손잡이12.5mm에서 여유2.5mm를 뺀 하한10mm(0.010m)를 **엄격히 초과**해야 하며 목표폭0 도달은 요구하지 않는다. grip_detected만으로 성공하지 않는다. 빈손·통신 실패·중단·들어 올린 뒤 유지검사는 보존한다. world 최소 치수 자동계산으로 승인 하한을 대체하거나 B 공용 빈손·서랍 손잡이 기준을 바꾸지 않는다.

place는 놓은 뒤 목적지의 기대 물품·개수를 새 관측으로 검증한다. 서랍 내부 place도 해당 서랍 top view에서 재촬영하며 이동은 B 안전 검사·C 차단을 우회하지 않는다. 트레이의 정상 관측 미검출에만 현재 실행의 기대 목록·개수·목적지를 안내하는 사용자 확인을 적용한다. 서랍의 미검출/가림·관측 오류를 사용자 yes로 성공 처리하지 않는다. 최초 질문 뒤 첫 모호 응답은 한 번만 재질문하고 이전 답을 무효화한다. 같은 확인 절차의 중복 시작·재전송·종료 후 재시작으로 상한을 초기화하지 않는다. 명시 yes는 사용자 확인 근거로 비전 근거와 분리한다. 명시 no·두 번 모호·무응답/시간 초과·관측/음성/TTS 오류는 실패/확인 불가로 종료하며 성공 effect·완료 안내·다음 일반 동작을 차단한다. 자동 다시 놓기/동작 재시도는 없고 정리 모션도 실제 안전 상태와 기존 차단 검사를 통과해야 한다. 이미 이동했을 수 있는 물품의 이전 위치를 확실한 현재 상태로 재사용하지 않는다. 정지/cancel은 재개 보존 정책, 실제 놓침은 새 run 예외를 우선한다.

트레이 확인 응답은 같은 질문의 실제 TTS 완료≤새 녹음 시작≤녹음 끝≤Whisper SDK 요청 순서와 접수 구간, SDK 요청→STT 결과 구간을 각각 확인한다. 구간 값은 [E 설정 원본](../ros2_ws/src/ready2go_voice/params/voice.yaml), C 전체 최종 판정 기한은 C 실행 설정에서 관리하고 답 수신만으로 전체 기한을 충족했다고 보지 않는다. #152 질문 등록/시간값을 #43에 자동 적용하지 않는다. 최종 질문/응답 판정은 일회성이며 중단 시 무효화한다. C가 verify 대기·최종 effect·상태/로그·성공 안내를 담당하며 E는 응답 증빙·분류를 담당한다. 구조화 verify/evaluator·새 상태/오류/모드는 계약 승인 전 미확정이다. P1 실행 응답 기반 effect와 P2 실제 검증→effect 차단/반영을 구분한다.

복합 handover_with_unpack 전체 성공은 목표 물품의 트레이 place 검증, 치운 물체의 역순 복구·재식별·복구 후 실제 관측, 실제 빈손 및 실행 목표/태스크의 최종 서랍·복귀 위치와 저장 상태 일치가 모두 충족되어야 한다. 원위치 위치 오차는 [AC-ACT-03](#ac-act-03)을 따르고 방향 오차도 기록한다. 명령 pose·복구 스택 소진만으로 실제 복구를 증명하지 않는다. 전달만 성공한 부분 결과와 전체 성공을 구분하며 자동 재집기/전체 재실행은 하지 않는다. 모든 목표를 닫힘/home으로 재정의하지 않으며 실제 빈손 근거가 불명확하면 안전 허가를 내지 않는다. 파지 폭 하한은 파지 성공 기준으로서 빈손 증거를 대신하지 않는다.

open_drawer의 기존 verify는 유지한다. close_drawer는 닫기 밀기 목표위치 도달의 B close_confirmed 근거로 판정하며 허용오차와 힘 안전검사를 보존한다. 후퇴/home은 닫힘 검증 근거가 아니며 B 실측 완료를 주장하지 않는다. 완료 판정은 [AC-ONT-01](#ac-ont-01)·[AC-LOG-01](#ac-log-01)을 따르며 문자열 선언·E 내부 정책/모의 시험·P1 log 모드 effect를 P2 운영 완료로 보지 않는다.

### P2 재개 응답 접수 — FR-SAF-03 / AC-SAF-04

[사용자 결정: #152] 질문과 중단 작업의 수명을 분리한다. 질문 만료·등록 확인 실패·TTS 실패·질문의 “아니/아니요”는 질문만 무효화하고 중단 작업은 보존한다. 일반 cancel도 재개 가능한 중단이며 자동 재개·그리퍼 조작·잠금 해제는 없다. 명시적 작업 종료, 재개 작업 완료, Runner 재기동/상태 초기화는 기존 재개 대상을 끝낸다. E만 재기동하면 과거 질문/음성은 무효화하고 현재 C 보존 상태를 재조회한다. 다른 새 작업 요청은 기존 보존 작업을 유지한 채 거절한다.

작업 종료는 현재 대상이 특정되고 “종료” 의도가 명확해야 한다. “종료/작업 종료해/이 작업 종료해”와 “계속하지 말고 종료해”는 종료 의도이며 “종료하지 마/종료 안 할게/종료하지 말고 이어서 해”는 종료가 아니다. 단순 문자열 포함이나 질문 거절을 작업 종료로 해석하지 않는다. 종료 요청은 모션/잠금 해제/새 작업 허가가 아니며 구체 종료 wire는 계약 승인으로 확정한다.

현재 유효 상태로 확인한 boot 전체 최대 seq와 같은 run/halt 순서를 검사해 낮거나 같은 seq·이전 boot/사건을 폐기한다. seq는 실제 관측 신선도 증거가 아니다. C의 복구 확인·사전 검사 뒤 현재 사건의 질문 후보를 E가 고유 ID로 TTS 전에 등록 요청한다. 같은 현재 사건/boot의 유효한 최신 상태에서 C 등록을 확인한 뒤에만 TTS를 시작한다. 등록은 재개 허가가 아니며 동일 ID 재전송은 질문·실행·기한을 늘리지 않는다. 사건당 새 질문을 임의 반복하지 않는다.

질문 답은 현재 boot/run/halt/질문과 실제 TTS 완료≤새 녹음 시작≤녹음 끝≤Voice Whisper SDK 호출 직전 시각을 결합한다. TTS 완료부터 SDK 요청까지 접수 기한은 기존 10초(10.0 포함)를 유지하며 SDK 요청부터 정상 STT 결과까지는 별도 유한 처리 구간이다. 등록 요청→등록 확인, 확인→TTS 준비/실제 완료의 큐·준비 지연도 각각 검사한다. 초기 E 구간 값은 [voice.yaml](../ros2_ws/src/ready2go_voice/params/voice.yaml)이 원본이며 C 후보·등록 질문·독립 요청 기한은 C 설정/시계 소유로 구분한다. 질문의 유효 기한은 작업 보존 기한이나 독립 요청 기한이 아니다. progress 이벤트나 UTC 표시를 SDK/녹음 증빙으로 대신하지 않고 E/C 절대 monotonic 값을 직접 비교하지 않는다. 정확 포함 여부가 미확정인 경계는 계약에서 대조하며 안전측 보류한다.

질문 만료/거절 뒤 새 명시 “이어서 해”는 재질문 없는 독립 재개 요청으로 검사할 수 있다. 고유 요청 ID·현재 boot/run/halt의 유일한 대상·새 녹음과 SDK/STT 순서·C 등록 확인·일회성 소비를 요구한다. 새 녹음 시작부터 STT·발화 분류·C 등록 확인 전체와 그 안의 STT 처리 구간은 E 설정으로 각각 검사한다. 질문의 접수창을 독립 요청에 전용하지 않는다. 만료 후 “응”, 과거 질문 녹음·늦은 STT를 새 독립 요청으로 재분류하지 않으며 실패/만료는 요청만 무효화하고 작업은 보존한다.

재개는 B의 실제 정지·외력 없음·정상/신선한 센서/통신/컨트롤러 상태, C의 현재 그리퍼/물품·pre/재진입·부분 effect 중복 검사, E/C의 현재 유효 요청을 모두 통과해야 한다. B의 관측 check와 실제 복구/리셋·C 잠금 해제를 분리한다. 불명확/누락 관측은 안전 허가가 아니며 C 실행 직전 재검사를 유지한다. 재정지·상태/boot 변경·과거/중복 응답은 질문/요청을 무효화한다. wire/등록 ACK/증빙·종료/작업 수명은 실행 원본·예시·ICD 및 E 포함 2인 승인 후 연결한다. 자동 그리퍼 정규화·while/fallback 재개 확대는 제외한다.

place 중 놓침은 아래 [새 실행 예외](#halt-motion-policy)를 적용하며 일반 취소의 단계 재개로 처리하지 않는다.

### 모션 차단·놓침 후 새 실행 정책 — NFR-SAF-02 / FR-SAF-03

[문서: 사용자 승인 E-78-HALT-MOTION-20261009-01] [#78 결정](https://github.com/Jik-Kim/ready2go/issues/78#issuecomment-6077437823)에 따라 `HALT_MOTION`은 `OBJECT_DROPPED`·`ESTOP`·`SENSOR_INVALID`와 기존 `STOP_UNCONFIRMED`·`STATE_UNKNOWN`·`MOVE_UNCONFIRMED`·`LOCKED`의 보호를 포함하는 차단 분류이다. 재개 허용 목록이나 새 wire enum이 아니다. 오류 발생 즉시 B 정지 요청과 C 공통 잠금으로 후속 이동·그리퍼 명령을 차단하며 retry/fallback/skip/safe_home/finally·새 task·재개가 이를 우회해서는 안 된다. 정지 요청·잠금과 실제 로봇 정지 확인은 별도 근거로 기록한다. B가 정상 관측의 실제 놓침과 비정상 센서값을 구분하며 센서/보유 불명확을 빈손·낙하로 단정하거나 성공 effect로 처리하지 않는다. 기존 pick의 `GRASP_FAILED`를 운반 중 놓침으로 바꾸지 않는다.

E는 원인·실제 정지·현재 대상의 확인 근거에 맞춰 안내한다. 실제 정지가 미확인이면 로봇 상태 확인을 우선하며 사람에게 물체 회수를 지시하지 않는다. 현재 사건에서 실제 정지와 대상이 확인된 놓침에는 “지우개가 떨어져 작업을 중단했습니다. 지우개를 다시 서랍에 넣어주세요.”처럼 안내할 수 있다. 센서 이상은 센서·물체 확인을 안내하며 빈손/낙하를 단정하지 않는다. 안내·TTS 실패로 잠금이나 요청 차단을 해제하지 않는다.

**place 중 놓침은 기존 run 종료·잠금 유지 → 사람의 물리 복원 → 실제 그리퍼·물체·서랍·작업영역 확인 → C 논리 상태 동기화 → B/C 안전 조건 확인 → 명시적 새 시작 → 새 run에서 처음부터 실행**한다. 사용자 “다시 넣었어”만으로 상태를 쓰거나 실행을 허용하지 않는다. 기존 place 재개·이전 pick rollback·자동 재집기·과거 좌표/보유 기억/성공 effect 재사용은 제외한다. 실제 확인이 불가능하거나 확인에 이동이 필요한 경우의 안전 복구 절차는 B/C 협의 전 미확정이며 일반 task 이동을 잠금 중 임의 허용하지 않는다.

일반 cancel과 다른 재진입 가능한 정지는 [#152 접수·재진입 기준](#resume-admission-policy)을 유지한다. `SENSOR_INVALID`는 센서 정상화·현재 실제 상태 확인 전 재개를 거절한다. P1 [FR-ACT-03](#fr-act-03)·[FR-ONT-01](#fr-ont-01)·[FR-COM-01](#fr-com-01)·[NFR-SAF-02](#nfr-saf-02)와 [AC-SAF-01](#ac-saf-01)의 안전 범위를 유지하며, P2 복구·상태·로그와 새 실행 예외는 [FR-SAF-03](#fr-saf-03)·[FR-ONT-02](#fr-ont-02)·[FR-LOG-02](#fr-log-02)·[AC-SAF-04](#ac-saf-04)에 연결한다. Phase·수용 숫자는 변경하지 않는다. 정책 승인과 담당 수락·신규 계약 승인을 구분하며 wire/상태 표현·운영 연결은 B/C 협의 및 실행 원본·예시·문서 동시 반영, E 포함 2인 승인 뒤 진행한다. E 선언·내부 모의 준비를 B/C 공통 차단이나 실물 수용 완료로 보지 않는다.
