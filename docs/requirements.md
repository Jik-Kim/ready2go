# Ready2Go 요구사항 기준 문서

> **문서 역할:** 프로젝트 목표, 범위, 기능·비기능 요구사항, Phase 진입·완료 기준의 단일 기준 원본(Single Source of Truth).
> 구현 상세는 주제별 문서에 두고, 해당 문서에서 이 문서의 요구사항 ID를 참조한다. 기준이 충돌하면 이 문서가 요구사항과 범위를 결정하고, 상세 문서는 구현 방법을 결정한다.
> 관련 문서: [문서 인덱스](README.md) · [시연 시나리오](demo_scenario.md)

## 1. BRD — 비즈니스 요구사항

### 1.1 목표

1. **음성 기반 물품 탐색·전달:** 한국어 음성 명령을 받아 서랍 안의 지정 물품을 찾아 전달 트레이에 놓는 협동로봇 시스템을 구현한다.
2. **온톨로지 기반 스킬 조합:** 작업 공간, 물품, 로봇 상태, 스킬의 조건과 결과를 온톨로지로 표현하고, 플래너가 목표 달성을 위한 실행 순서를 생성한다.
3. **가림 물체 탐색·복구:** 목표가 가려진 경우 장애물을 임시 위치로 옮겨 탐색하고, 종료 후 이동한 물체를 복구한다.
4. **수업 기술 통합:** ROS 2 Jazzy, RealSense와 카메라 보정, YOLO 학습·추론, 음성 처리, Doosan M0609, OnRobot RG2·Modbus, Docker, 다중 PC 통신, 데이터베이스를 연동한다.
5. **단계적 개발:** 실물 기본 탐색부터 완성하고, 동적 플래닝·가림 처리·다중 서랍 탐색으로 확장한다. 시뮬레이션과 mock은 개발·사전 검증에 사용하며 실물 안전 절차를 대체하지 않는다.

## 2. Phase 범위

Phase는 기능 단위이며 순서대로 누적한다. Phase 1만으로도 음성·비전·실물 Pick and Place·Docker·DB 등 수업 필수 스택이 동작해야 한다. **온톨로지 조건·결과에서 플래너가 스킬 순서를 도출하는 장면은 Phase 2의 필수 완료 기준**이다.

- Phase 1만 완성되어도 강사 챌린지 3요소(동작·상태 JSON, JSON 조합, 성공 여부 로그)를 최소 충족한다. 일정이 밀려도 프로젝트가 성립하도록 하기 위함이다.
- 다음 Phase 기능은 이전 Phase 완료 기준을 통과한 뒤 착수한다. 단, 데이터 수집·트윈 씬 구성 등 다음 Phase의 선행 작업은 병행할 수 있다.

Phase 배정을 바꿀 때는 아래 FR/NFR 표를 먼저 수정하고, 관련 주제 문서의 요구사항 ID 링크와 필요한 작업 요약을 **같은 PR에서** 확인·갱신한다. 주제 문서의 안내는 이 문서의 기준을 복제하지 않으며, 관련 ID를 가리킨다.

| 단계 | 포함 범위 | 완료 기준 | 관련 요구사항 |
|---|---|---|---|
| **Phase 1 — 기본 음성 Pick and Place** | 음성·키워드 추출, 기본 온톨로지와 선언형 태스크 실행, RealSense 보정·YOLO, Doosan/RG2 제어, MongoDB 로그, Docker와 다중 PC 통신 | “헬로 로키, 시계 찾아줘” → 위 서랍 열기 → 보이는 시계 집기 → 전달 트레이에 놓기 → 서랍 닫기 → 홈 복귀. 실패하면 `finally`로 서랍을 닫고 홈으로 복귀한다. 스텝별 결과를 MongoDB에 저장한다. | [FR-INT-01–03](#fr-int-01), [FR-ONT-01](#fr-ont-01), [FR-PLN-01](#fr-pln-01), [FR-VIS-01–02](#fr-vis-01), [FR-ML-01](#fr-ml-01), [FR-ACT-01–03](#fr-act-01), [FR-LOG-01](#fr-log-01), [FR-COM-01–02](#fr-com-01), [NFR-ENV-01](#nfr-env-01), [NFR-DB-01](#nfr-db-01), [NFR-SAF-01–02](#nfr-saf-01) |
| **Phase 2 — 온톨로지 계획과 가림 복구** | 스킬 조건·결과 기반 자동 계획, 사후 관측 검증, 가림 순서, Unpacking, LIFO 복구, 상세 로그, 트윈 미러링 | 가려진 목표를 찾아 장애물을 복구한다. 별도의 동작 순서를 코드에 하드코딩하지 않고 플래너가 목표에서 스킬 조합을 생성하며, 계획과 조건 확인을 로그에서 확인할 수 있다. | [FR-ONT-02](#fr-ont-02), [FR-PLN-02](#fr-pln-02), [FR-VIS-03](#fr-vis-03), [FR-ACT-04](#fr-act-04), [FR-LOG-02](#fr-log-02), [FR-TWN-01](#fr-twn-01), [NFR-ABS-01](#nfr-abs-01), [NFR-TWN-01](#nfr-twn-01) |
| **Phase 3 — 다중 서랍과 지식 확장** | 목록·분류형 명령, 다중 서랍, 클래스 추론, 관측 불일치 처리, 트윈 사전 검증, 선언형 복합 스킬 추가, 선택적 SAM2 | 목록 요청으로 여러 서랍을 탐색한다. 상태 불일치를 감지해 기록하고, 관측 신뢰도에 따라 상태를 갱신하거나 사용자 확인을 요청한다. | [FR-INT-02](#fr-int-02), [FR-ONT-03](#fr-ont-03), [FR-PLN-03](#fr-pln-03), [FR-VIS-04](#fr-vis-04), [FR-REC-01](#fr-rec-01), [FR-TWN-02](#fr-twn-02), [NFR-TWN-01](#nfr-twn-01) |

| <a id="nfr-saf-02"></a>NFR-SAF-02 | 실패·취소 안전 처리 | 타임아웃, 파지 실패, 통신 단절, 사용자 취소, 비상정지 시 안전 상태와 복구 책임자를 정의한다. 비상정지 후 자동 동작 재개를 금지한다. | P1 |
| <a id="nfr-twn-01"></a>NFR-TWN-01 | 트윈 검증 경계 | 시뮬레이션으로 확인한 항목과 실물에서 별도 확인할 항목을 구분한다. 트윈은 시각화·사전 점검 도구이며 실물 안전 검증을 대체하지 않는다. | P2–P3 |
