# 시연 시나리오 — 등록 물품 요청과 단계별 확장

> 관련 기준: [UC-P1–P3](requirements.md#use-cases), [AC-DEMO-01](requirements.md#ac-demo-01). 물품 원본은 `knowledge/world.jsonld`, 실물 파지 상태는 [hardware.md 2.3](hardware.md#23-물품-선정-기준-day-2-실물-파지-테스트로-확정).

## 17. 시연 원칙

이 문서는 requirements.md의 검증 절차와 예시이며 기능 범위·Phase·완료 기준을 새로 정하지 않습니다. 아래 절차는 설계된 시연안으로, 실제 완료 여부는 요구사항별 실행 기록으로 판정합니다. [문서]

- **P1은 등록된 물품 중 사용자가 요청한 단일 물품을 전달함.** 지우개·립밤·차키 등 아래 대사는 예시이며 요청 가능한 물품의 고정 목록이 아님.
- 인식 목록 11종은 파지 승인 완료를 뜻하지 않음. 실제 시연은 B·E가 설정·파지·배치를 확인한 물품으로 수행하고, 미확정 요청은 실행 불가/확인 필요를 안내함. 그 연결은 B·C 구현이 필요함.
- `initial_state.json`은 위 서랍 배치의 예시 프리셋. 실제 배치 확인 후 명시적으로 초기화하고 상태 조회 때마다 다시 적용하지 않음.
- 기존 시계·지갑 시나리오는 현재 등록 목록에서 제거됨. 새 P3 목록·배치는 아래 예시를 바탕으로 팀이 확정하며, 과거 10/02 합의를 새 구성의 확정 근거로 사용하지 않음.

### 17.1 P1 — 단일 물품 요청

검증 대상: FR-ONT-01, FR-PLN-01, FR-INT-01–03, FR-VIS-01–02, FR-ACT-01–03, FR-LOG-01, UC-P1 ([requirements.md](requirements.md)). [문서]

1. 사용자가 "헬로 로키, 지우개 찾아줘"처럼 **등록된 물품 하나**를 요청함.
2. 음성 해석은 물품 키(`eraser`)를 만들고 온톨로지 어휘로 검증함.
3. 파지 설정·실제 위치를 확인하고, 서랍 열기 → 관측 → 집기 → 전달 트레이에 놓기 → 서랍 닫기 → 홈 복귀.
4. 진행·성공·미발견·실행 불가를 음성으로 안내하고 단계별 결과를 기록함.

목표가 가려졌다면 P1은 보이는 물품 조건을 충족하지 않음. P1에 장애물 제거·다중 물품·목록 요청을 추가하지 않음. 실패·취소는 기존 안전 계약에 따르고 비상정지 후 자동 복구하지 않음.

### 17.2 P2 — 가림 탐색·원위치 복구

검증 대상: FR-PLN-02, FR-ONT-02, FR-VIS-03, FR-ACT-04, FR-LOG-02, UC-P2 ([requirements.md](requirements.md)). [문서]

예시: `cover_plate` 아래 `eraser`를 배치하고 지우개를 요청함. 판의 전체 높이 40.5 mm와 아래 공간 21 mm·다리 간격은 #8 실측 기준이며, 실제 숨김·인식·파지는 별도 확인함.

**S2 배치 확인:** 립밤 몸체 전체를 지우개의 파지 손가락 공간 밖에 배치함. 시험 배치는 립밤 중심을 지우개 중심에서 **95 mm 이상** 떨어뜨리고, 지우개는 벽에서 떨어진 서랍 가운데 쪽에 둠([현재 계산 근거·PC2 확인 절차](../practice/C/2026-10-13_pc2_checklist.md#1-1012-남은-확인--unpacking-find_with_unpack), #299). 이는 실물 파지 승인값이 아닌 계산 기반 시험 배치 조건임. 긴 변 양끝을 잡는 경우 양끝 바깥의 벌림·하강 공간도 확보함. 판 손가락 자리와 원래 자리 복구 공간을 함께 비우며, 판 제거 후 재관측과 B 사전 검사로 실제 파지 방향·그리퍼 벌림·립밤의 크기와 방향에 따른 간섭 여부를 확인함. 최종 실물 파지 가능 여부는 B가 별도로 확인함.

서랍 열기 → 관측 → 목표가 가려져 있으면 검증된 장애물을 같은 서랍 내부 빈 공간으로 옮김 → 재관측 → 목표를 전달 트레이(`handover_zone`)에 전달 → 이동한 장애물 LIFO 원위치 복구 → 닫기·홈. 등록 이름은 `handover_with_unpack`, 태스크 참조는 `tasks/find_with_unpack.json`이나 현재 파일은 이전 트레이 방식 예시로, 서랍 내부 배치·복구 계약 반영 전 실행 기준으로 사용하지 않음. 빈 공간이 없으면 실행 불가로 안내하며 외부 임시 트레이로 우회하지 않음. 구현·계약 인계는 [domain.md 8.2~8.3](domain.md) 참조. 같은 클래스 두 개가 동시에 있으면 인스턴스 선택·추적을 A·C 계약으로 먼저 정해야 함.

P2 자동 계획 예시: "립밤을 아래 서랍에 넣어 둬". 목표 상태를 받아 스킬 조건·결과에서 순서를 생성하고 계획 확인 후 실행함. 대상·목표는 예시이며 특정 물품 전용 플래너가 아님.

### 17.3 P3 — 목록·다중 서랍·상태 수정·새 작업

검증 대상: FR-ONT-03, FR-PLN-03, FR-REC-01, FR-INT-02, UC-P3 ([requirements.md](requirements.md)). [문서]

- "출근 준비물 찾아줘" 등의 목록·분류 요청은 **P3**. `commute_set`의 에어팟 케이스·차키·립밤은 참조 정합성 유지용 예시 구성으로, 실제 출근 준비물 구성을 확정하거나 P1 요청 범위를 제한하지 않음.
- 다른 서랍에서 남은 목표 발견, 관측/기록 불일치 처리, `return_items` 등록 등은 해당 요구사항 단계에서 수행함.
- 숨김 대상·서랍별 실제 배치·의도적 상태 불일치는 리허설 전에 별도 확정함. P1 프리셋에 임의의 실제 위치나 일부러 틀린 기록을 섞지 않음.

### 17.4 화면·로그와 종료

화면은 선택된 Phase의 실행 확인을 보조함. P1은 FR-LOG-01의 스텝 결과, P2는 FR-LOG-02의 상세 조건·관측 검증 기록을 확인함. 표시 화면 자체가 기능 완료 기준을 추가하지 않음. 최종 전달과 복구 상태를 확인하고 로그를 조회함. 트윈은 단계별 보조 도구이며 실물 검증을 대체하지 않음.

P1 최소 표시는 별도 GUI 없이 분할 터미널로 대체할 수 있으며, D가 배치·실행 안내·캡처를 준비하고 C가 데이터 연결을 검토함. 다음 항목의 출처와 연결 여부를 확인함. [문서]

| 표시 항목 | 제공·인계 담당 | 확인 범위 |
| :--- | :--- | :--- |
| STT 원문·인텐트/LLM 결과 | E → D, C 연결 검토 | 실제 출력 경로·사용 버전 제공. 음성 패키지 연결 완료는 별도 확인 |
| 실행 ID·실행 상태·현재 스텝 | C → D | C가 제공하는 진행 정보와 대조. 종료 로그만으로 실시간 현재 스텝 제공을 가정하지 않음 |
| 서랍·그리퍼·물품 상태 | C 제공, E 의미 확인 → D | P1은 성공 응답 후 effect 반영 상태. P2의 사후 관측 verify 완료로 표현하지 않음 |
| 단계별 시각·상태·오류 코드와 종료 로그 | C → D | MongoDB 조회 방법·레코드 예시와 DB 장애 시 JSONL 조회 경로 제공 |

연결되지 않은 정보는 **미연결/데이터 없음**으로 표시하고 mock·녹화 자료는 실제 실행 자료와 구분함. D의 구성 준비, C·E 데이터 연결, 실물 통합 검증을 각각 확인함. A의 실물 카메라·트윈 결합은 후속 협의이며 트윈 미러링은 P2 범위임. 담당별 진행과 완료 조건은 [#59](https://github.com/Jik-Kim/ready2go/issues/59)에서 추적함. [문서]

### 17.5 시연 레벨과 리셋

| 레벨 | 범위 |
| :--- | :--- |
| L1 / P1 | UC-P1: 음성 단일 요청·보이는 목표 전달·닫기·홈·실행 응답 기반 상태와 로그 |
| L2 / P2 | L1 + 가림 탐색·LIFO 복구·목표 기반 자동 계획 |
| L3 / P3 | 목록·다중 서랍·상태 불일치 처리·등록형 복합 작업 |

리허설에서 검증된 범위로 시연함. 물품 이름은 고정 기능이 아니며 실제 파지 승인과 배치 확인이 선행됨. 리셋은 위치 표시·사진·프리셋과 실제 상태를 대조한 뒤 수행함.

### 17.6 담당별 인계

- A: 고정된 config/yolo_classes.txt 사용·라벨링(PR #45의 sources.world 조회 반영), 좌표/yaw 계약 및 같은 클래스 인스턴스 구분.
- B: 물품별 파지 힘·파지점·반복성·지우개 높이 기준/예외 검증, 미확정 설정 사용 차단.
- C: 물품 설정 조회 결과·상태 초기화·실행 가능 여부·실패/TTS 계약과 로그 연결. D에게 실행 상태·현재 스텝 제공 경로와 MongoDB/JSONL 조회 방법·레코드 예시를 인계하고 표시 연결을 검토함.
- E: 원본 물품 정의·음성 어휘·공용 규칙, B와 실물 승인 정리. D에게 STT 원문·인텐트/LLM 결과 출력 경로를 제공하고 온톨로지 상태 의미를 확인함.
- D: 최소 표시 구성·분할 터미널 배치·실행 안내·캡처(C 연결 검토), 실제 배치·시도 횟수·성공/실패 기록과 시연 영상. 타 담당 패키지의 데이터 제공 구현은 해당 담당에게 인계함.
