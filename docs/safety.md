# 안전 요구사항

> 관련 요구사항: [NFR-SAF-01–02](requirements.md#nfr-saf-01), [NFR-TWN-01](requirements.md#nfr-twn-01). 실물 작업 절차와 안전 게이트 상세는 이 문서에서 다룹니다.

## 11. 안전 요구사항 (실물)

* **비상정지**: 티치 펜던트 비상정지 버튼을 1차, `/runner/estop` 서비스 + PC2 키보드 단축키를 2차, 음성 "멈춰"는 보조 수단으로 둠.
* **툴 설정 확인**: 로봇 전원을 켤 때마다, 그리고 측정(3점 터치 등)·자동 동작 전에 펜던트 활성 TCP = `GripperDA_v1`, 툴 = `tool_weight`인지 확인(기준값 `config/calibration/calibration_meta.yaml`, 결정 #28). 풀린 채 찍으면 좌표가 플랜지 기준으로 읽혀 z가 228 mm 틀어지고(#6, PR #58), 자동 동작하면 손끝이 약 23 cm 아래로 내려가 충돌한다. 스킬도 시작 시 확인해 다르면 `TOOL_NOT_SET`으로 거부([runner.md 7.1](runner.md)).
* **실물 실행 절차**: 새 JSON·새 동작은 ① mock 또는 sim에서 먼저 통과 → ② 실물 저속 실행 → ③ 정상 속도. 실물 실행 중에는 **1인이 비상정지 버튼을 잡고 대기**(2인 운용).
* **실물 실행 전 안전 게이트 (Runner가 순서대로 확인, 단계별 결과를 로그에 기록)**
  1. 스키마 검증(LLM 출력·태스크 JSON)
  2. 온톨로지·현재 상태 검증(존재하는 물품인지, 목표가 현재 상태와 다른지)
  3. 계획 존재 확인(BFS 실패 시 이유를 TTS로 알리고 실행하지 않음)
  4. **목표형 명령은 계획을 화면·TTS로 제시하고 사용자 확인**("진행할까요?" → "응")
  5. 새 JSON·LLM 생성 JSON은 기호적 드라이런 + 트윈 사전 검증
  6. 스킬별 실행 시점 조건 재확인(관측 기반: 서랍이 실제로 열렸는가)
  7. 협동 모드 속도·힘 제한, 작업 영역 제한, 비상정지 버튼 2인 운용
  8. 사후 관측 확인(`verify`) 후에만 상태 갱신
* **속도·힘 제한**: DSR 협동 모드 속도·힘 제한 적용. `handover_zone`·서랍 접근 시 감속.
* **전달 방식**: 사람 손에 직접 건네지 않고 전달 트레이에 내려놓음.
* **작업 영역 제한**: 백엔드에서 작업 영역 밖 목표 포즈는 실행 전에 거부(`WORKSPACE_VIOLATION`).
* **실물 운용 순서 (B, #19)** — 수치는 `[팀 확정 필요]`, 10/06 E-stop 실습 때 정한다.
  1. **역할**: 조작자 1명(PC2·펜던트) + **비상정지 담당 1명**(펜던트 비상정지 버튼을 손에 들고 로봇에서 눈을 떼지 않음). 둘이 없으면 자동 동작을 하지 않는다.
  2. **시작 점검**: 펜던트 활성 TCP·툴 확인(위 항목) → 작업 영역에 사람·물건 없음 → 서랍장·트레이 위치 표시와 일치 → `docker compose --profile real up` → `/gripper/state` 수신 확인.
  3. **저속 → 정상 속도**: 새 동작·새 JSON·바뀐 포즈는 ① 저속(협동 모드, 속도 비율 `[팀 확정 필요]`)으로 1회, 경로·간섭을 눈으로 확인 → ② 같은 저속으로 1회 더(재현성) → ③ 정상 속도. 한 단계라도 이상하면 처음부터. 교시값이 바뀐 포즈(예: `drawer_approach` ↔ `drawer_top_view`, J1 약 58° 차이)는 첫 이동을 반드시 저속으로.
  4. **비상정지**: 1차 펜던트 버튼(하드웨어, 가장 빠름), 2차 PC2 키보드 단축키 → `/runner/estop`(Runner `halt()` → `ABORTED`), 보조 음성 "멈춰". 이상하다고 느끼면 묻기 전에 누른다.
  5. **비상정지 뒤**: 펜던트에서 원인 확인(충돌·끼임·좌표 오류) → 사람이 로봇을 안전 위치로(직접교시 또는 저속 조그) → 펜던트 비상정지 해제·서보 켜기 → 툴 설정 다시 확인 → Runner `resume()`. `finally`의 로봇 동작은 자동 실행하지 않는다(아래 항목). 원인과 조치를 이슈에 한 줄 남긴다.
  6. **종료**: 그리퍼 비우기 → `home` → 서랍 닫힘 확인 → 서보 끄기.

* **비상정지 후 처리**: E-stop으로 `ABORTED`된 경우 `finally`의 로봇 동작을 자동 실행하지 않고, 사람이 확인한 뒤 재개(7.1 실패 처리 규칙).
