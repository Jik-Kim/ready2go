> 관련 요구사항: [NFR-SAF-01–02](requirements.md#nfr-saf-01), [NFR-TWN-01](requirements.md#nfr-twn-01). 실물 작업 절차와 안전 게이트 상세는 이 문서에서 다룹니다.

## 11. 안전 요구사항 (실물)

* **비상정지**: 티치 펜던트 비상정지 버튼을 1차, `/runner/estop` 서비스 + PC2 키보드 단축키를 2차, 음성 "멈춰"는 보조 수단으로 둠.
* **툴 설정 확인**: 로봇 전원을 켤 때마다, 그리고 측정(3점 터치 등)·자동 동작 전에 펜던트 활성 TCP = `GripperDA_v1`, 툴 = `tool_weight`인지 확인(기준값 `config/calibration/calibration_meta.yaml`, 결정 #28). 풀린 채 찍으면 좌표가 플랜지 기준으로 읽혀 z가 228 mm 틀어지고(#6, PR #58), 자동 동작하면 손끝이 약 23 cm 아래로 내려가 충돌한다. 스킬도 시작 시 확인해 다르면 `TOOL_NOT_SET`으로 거부([runner.md 7.1](runner.md)).
* **실물 실행 절차**: 새 JSON·새 동작은 ① mock 또는 sim에서 먼저 통과 → ② 실물 저속 실행 → ③ 정상 속도. 실물 실행 중에는 **1인이 비상정지 버튼을 잡고 대기**(2인 운용).
* **실물 실행 전 안전 게이트 — 구현과 계획 구분**
  * **P1 Runner 구현**: ① 태스크 스키마·P1 허용 블록/필드 검사(실패 시 동작 없이 `TASK_INVALID`) ② 스킬 실행 직전 Runner가 들고 있는 상태에 대한 온톨로지 `pre` 검사(실패 시 동작 없이 `PRE_UNMET`) ③ 하위 원자 동작이 모두 성공 응답을 반환하면 스킬 `effect`를 상태에 반영. 실행 기록에는 실제 수행한 스텝의 검사 결과(`pre_check`)와 응답 기준 상태 변화(`state_diff`)를 남긴다. P1의 `pre` 검사는 서랍이 실제로 열렸는지 새로 관측하는 검사가 아니며, 성공 응답만으로 반영한 상태를 관측으로 확인했다는 뜻도 아니다.
  * **P1 백엔드 구현**: 스킬 시작 전 TCP·툴을 확인하고, 관절 목표·이동 중 관절 제한, 서랍 인출 거리, yaw 유효성, 바닥 위 여부와 벽·파지 조건을 각 경로에서 검사한다([runner.md 7.1](runner.md), [`motion_guard.py`](../ros2_ws/src/ready2go_skills/ready2go_skills/core/motion_guard.py), [`skill_server.py`](../ros2_ws/src/ready2go_skills/ready2go_skills/nodes/skill_server.py)). 공통 목표 포즈의 작업 영역 경계를 검사하는 코드는 없으며, `skill_server._line()`도 별도 작업 영역 검사 없이 이동 명령을 보낸다. 따라서 현재 백엔드가 모든 동작의 작업 영역을 자동 검사한다고 보지 않는다.
  * **P1 사람 절차**: 작업 영역에 사람·물건이 없는지, 서랍장·트레이가 표시 위치와 일치하는지 시작 전에 확인하고 새 포즈·경로는 저속으로 눈으로 확인한다. 협동 모드 속도·힘 제한과 비상정지 2인 운용도 아래 실물 운용 순서를 따른다. 이 사람 점검과 백엔드의 개별 검사를 Runner가 하나의 8단계 게이트로 순서대로 자동 검사·기록하는 구현은 현재 없다.
  * **P2 계획**: 현재 상태와 온톨로지 조건·결과로 BFS 계획을 만드는 것은 FR-PLN-02, 실제 상태를 다시 보는 `verify`가 통과한 뒤에만 `effect`를 반영하는 것은 FR-ONT-02 범위다.
  * **P3 계획**: 실물 투입 전에 목표 포즈·계획의 도달성 등을 트윈에서 검사하는 사전 검증은 FR-TWN-02 범위다. P2의 FR-TWN-01은 실물 상태 미러링이며 사전 검증 완료를 뜻하지 않는다.
  * **미구현 전체 설계**: 계획 제시·사용자 확인과 전체 안전 게이트 결과의 `runs` 헤더 기록은 현재 P1 완료로 간주하지 않는다. 구현할 때 해당 기능의 요구사항 Phase를 따르며 P3 트윈 사전 검증을 P2 완료 조건에 포함하지 않는다.
* **속도·힘 제한**: DSR 협동 모드 속도·힘 제한 적용. `handover_zone`·서랍 접근 시 감속.
* **전달 방식**: 사람 손에 직접 건네지 않고 전달 트레이에 내려놓음.
* **작업 영역 제한 (자동 검사 미구현)**: 현재 공통 목표 포즈 경계 검사와 `WORKSPACE_VIOLATION` 반환 경로는 없다. P1은 위 사람 점검·저속 육안 확인을 적용한다. 향후 자동 검사를 추가할 때는 작업 영역 경계를 `config/`에 `[팀 확정 필요]` 값으로 두고, 모든 이동 명령 전에 같은 검사 경로를 거치도록 Skills 담당 B가 구현·시험한 뒤 에러 코드 표와 이 문서를 함께 갱신한다. 드라이버·펜던트의 별도 보호 기능은 실제 설정·거부 결과 근거가 확인되기 전 이 자동 검사 구현으로 간주하지 않는다.
* **실물 운용 순서 (B, #19)** — 수치는 `[팀 확정 필요]`, 10/06 E-stop 실습 때 정한다.
  1. **역할**: 조작자 1명(PC2·펜던트) + **비상정지 담당 1명**(펜던트 비상정지 버튼을 손에 들고 로봇에서 눈을 떼지 않음). 둘이 없으면 자동 동작을 하지 않는다.
  2. **시작 점검**: 펜던트 활성 TCP·툴 확인(위 항목) → 작업 영역에 사람·물건 없음 → 서랍장·트레이 위치 표시와 일치 → `docker compose --profile real up` → `/gripper/state` 수신 확인.
  3. **저속 → 정상 속도**: 새 동작·새 JSON·바뀐 포즈는 ① 저속(협동 모드, 속도 비율 `[팀 확정 필요]`)으로 1회, 경로·간섭을 눈으로 확인 → ② 같은 저속으로 1회 더(재현성) → ③ 정상 속도. 한 단계라도 이상하면 처음부터. 교시값이 바뀐 포즈(예: `drawer_approach` ↔ `drawer_top_view`, J1 약 58° 차이)는 첫 이동을 반드시 저속으로.
  4. **비상정지**: 1차 펜던트 버튼(하드웨어, 가장 빠름), 2차 PC2 키보드 단축키 → `/runner/estop`(Runner `halt()` → `ABORTED`), 보조 음성 "멈춰". 이상하다고 느끼면 묻기 전에 누른다.
  5. **비상정지 뒤**: 펜던트에서 원인 확인(충돌·끼임·좌표 오류) → 사람이 로봇을 안전 위치로(직접교시 또는 저속 조그) → 펜던트 비상정지 해제·서보 켜기 → 툴 설정 다시 확인 → Runner `resume()`. `finally`의 로봇 동작은 자동 실행하지 않는다(아래 항목). 원인과 조치를 이슈에 한 줄 남긴다.
  6. **종료**: 그리퍼 비우기 → `home` → 서랍 닫힘 확인 → 서보 끄기.

* **비상정지 후 처리**: E-stop으로 `ABORTED`된 경우 `finally`의 로봇 동작을 자동 실행하지 않고, 사람이 확인한 뒤 재개(7.1 실패 처리 규칙).
