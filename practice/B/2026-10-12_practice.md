1. **아침에 Docker 컨테이너가 GPU 를 못 잡음 (`could not select device driver "" with capabilities: [[gpu]]`)** [실측 PC2]
   - 증상: 어제까지 되던 `docker compose up` 이 GPU 오류로 실패, `nvidia-smi` 도 "couldn't communicate with the NVIDIA driver".
   - 원인: 밤사이 자동 업데이트로 커널이 `7.0.0-38` 로 올라감. NVIDIA 드라이버는 DKMS 로 커널마다 모듈을 따로 빌드해야 하는데 새 커널용 모듈이 빌드되지 않음(`modprobe nvidia` → 모듈 없음, `dkms status` 에 -38 없음). 드라이버 자체가 바뀐 게 아니라 **커널이 바뀌어 맞는 모듈이 없던 것**.
   - 조치: GRUB 에서 이전 커널 `7.0.0-34` 로 부팅 → `nvidia-smi` 정상, 컨테이너 정상.
   - 재발 방지(권고, 사용자 PC 설정): `sudo apt-mark hold linux-image-generic linux-headers-generic`(시연 전까지 커널 고정), `/etc/default/grub` `GRUB_DEFAULT` 를 -34 항목으로 + `sudo update-grub`. 커널을 올릴 땐 `sudo dkms autoinstall -k <새 커널>` 로 모듈이 빌드됐는지 확인 뒤 재부팅.

   - 조치: `git -c user.name=… -c user.email=… commit` 으로 작성자만 그 자리에서 주고, 작업 트리를 건드리지 않도록 임시 폴더에 새로 clone 해서 덤프만 커밋·push → 성공.

   - 원인: 비전 노드 로그 `code_sha 428f61d` — 가림 판정(`occluded_by`)이 들어간 `6d03249` 보다 **이전 코드로 빌드된 채** 떠 있었음. 비전 노드는 시작할 때 저장소 코드로 다시 빌드하므로, 코드를 pull 하기 전에 켠 컨테이너는 옛 코드 그대로.
   - 조치: main pull → 비전 노드(컨테이너) 다시 시작 → 로그의 `code_sha` 가 main 과 같은지 확인. 그 뒤 `occluded_by` 가 옴.
   - 교훈: **pull 하면 스킬 서버·비전 노드 둘 다 다시 켠다.** 켠 뒤 비전 로그 `code_sha`·가중치 sha 를 먼저 본다.

- main 최신화(10/12): A #234 비전 수정(가려진 물체 footprint 를 보이는 마스크로, 다 보이는데 조각만 난 건 '모름' 아님) · C #233 Runner `find_with_unpack` 머지 — 원위치 하나 실패해도 남은 것 계속, 하나라도 실패면 "옮긴 물건 일부를 원래 자리로 못 돌려놨어요" + FAILED `RESTORE_INCOMPLETE` → `B unpack` 도 같게.
