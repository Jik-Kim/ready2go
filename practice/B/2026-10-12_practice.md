### PC2 환경
1. **아침에 Docker 컨테이너가 GPU 를 못 잡음 (`could not select device driver "" with capabilities: [[gpu]]`)** [실측 PC2]
   - 증상: 어제까지 되던 `docker compose up` 이 GPU 오류로 실패, `nvidia-smi` 도 "couldn't communicate with the NVIDIA driver".
   - 원인: 밤사이 자동 업데이트로 커널이 `7.0.0-38` 로 올라감. NVIDIA 드라이버는 DKMS 로 커널마다 모듈을 따로 빌드해야 하는데 새 커널용 모듈이 빌드되지 않음(`modprobe nvidia` → 모듈 없음, `dkms status` 에 -38 없음). 드라이버 자체가 바뀐 게 아니라 **커널이 바뀌어 맞는 모듈이 없던 것**.
   - 조치: GRUB 에서 이전 커널 `7.0.0-34` 로 부팅 → `nvidia-smi` 정상, 컨테이너 정상.
   - 재발 방지(권고, 사용자 PC 설정): `sudo apt-mark hold linux-image-generic linux-headers-generic`(시연 전까지 커널 고정), `/etc/default/grub` `GRUB_DEFAULT` 를 -34 항목으로 + `sudo update-grub`. 커널을 올릴 땐 `sudo dkms autoinstall -k <새 커널>` 로 모듈이 빌드됐는지 확인 뒤 재부팅.
2. **덤프 파일 올리려는데 PC2 작업 트리에서 커밋·push 실패** [실측 PC2]
   - 원인: PC2 저장소에 `user.name`·`user.email` 이 없어 커밋이 안 만들어짐, 그 작업 트리는 로봇 작업 중이라 브랜치를 바꾸기도 곤란.
   - 조치: `git -c user.name=… -c user.email=… commit` 으로 작성자만 그 자리에서 주고, 작업 트리를 건드리지 않도록 임시 폴더에 새로 clone 해서 덤프만 커밋·push → 성공.
3. **`B view`·`B scan` 결과에 `OCCLUSION_UNKNOWN` — 쌓임 관계가 안 옴** [실측 PC2]
   - 증상: `B clear` 가 움직이기 전 `OCCLUSION_UNKNOWN`(가림 모름) 거부. 분할 모델 가중치는 맞음(`yolo11s_seg_ready2go_v1`, sha `5b9527b78ebf`).
   - 원인: 비전 노드 로그 `code_sha 428f61d` — 가림 판정(`occluded_by`)이 들어간 `6d03249` 보다 **이전 코드로 빌드된 채** 떠 있었음. 비전 노드는 시작할 때 저장소 코드로 다시 빌드하므로, 코드를 pull 하기 전에 켠 컨테이너는 옛 코드 그대로.
   - 조치: main pull → 비전 노드(컨테이너) 다시 시작 → 로그의 `code_sha` 가 main 과 같은지 확인. 그 뒤 `occluded_by` 가 옴.
   - 교훈: **pull 하면 스킬 서버·비전 노드 둘 다 다시 켠다.** 켠 뒤 비전 로그 `code_sha`·가중치 sha 를 먼저 본다.

## `B unpack` — 문서(C 진행표·Runner `find_with_unpack`) 그대로 한 번에 [사용자 10/12 "쌓기 해체, 가림막 빼기 풀로 돌리는 명령어 각각"]
- `B unpack top 몽키` (S1 쌓기 해체) / `B unpack bottom 지우개` (S2 가림막 빼기) / 지우개 빼고 `B unpack bottom 지우개` (S3 목표 없음 → 판·립밤 둘 다 원위치).
- 순서: 손잡이 앞 → 열기 → 탑뷰·인식 → Runner `select_obstacle`(덮은 것 맨 위부터, 옮긴 것 제외, 관계 모르면 한 번 다시 찍기) → 집기 → `aside_1`(움직이기 전 거부면 `aside_2`) → 다시 보기 … 최대 2개 → 목표 다 보이면 집기(벽에 막히면 넛지 뒤 다시) → 트레이 → 역순: `find_moved`(2 cm) → 집기 → 원래 pose(거부면 꺼냈던 고정 자리 + 안내, A안) → 마지막 다시 보기로 복구 오차(mm·°) → 닫고 홈.
- Runner 와 다른 점: 음성·`run_report`·트윈·온톨로지 상태 갱신 없음(B 실물 확인용). 판단은 Runner `core/unpack.py` 그대로 불러 씀.
- 쌓기 차키 원래 자리(캐러멜 위)는 놓기가 바닥만이라 `PLACE_BLOCKED` → 꺼냈던 `aside_1` 로(E #196 A안 답 전). 고정 자리에서 다시 집은 물체는 수직 집기라 원래 자리가 손잡이 벽 쪽 기울임 자리면 고정 자리로 남을 수 있음.

20. **`B unpack top 몽키` — 차키를 aside_1 에 잘 놓은 뒤 다시 보더니 캐러멜 대신 차키를 다시 집음** [실측 PC2]
   - 원인 [PC2 서버 로그로 확인]: 몽키 미검출(목표 못 찾음) → 위에 아무것도 없는 차키 먼저 aside_1 ✓ → 다시 보니 캐러멜(쌓임, 받침 약 20 mm, (60.5, 213.9) mm yaw −45°) 집기가 움직이기 전 `WALL_TOO_CLOSE` "뒤에서 밀어 손잡이 쪽 벽까지 (x −36 mm)" → `B unpack` 이 치울 물체 집기 실패를 바로 "목표 못 꺼냄"으로 보고 **역순 복구**(FR-ACT-04 "성공·실패와 무관하게 원래대로") → aside_1 의 차키를 집어 원래 자리(캐러멜 위)에 놓으려다 `PLACE_BLOCKED`(바닥만 지원) → 꺼냈던 aside_1 → 닫기·홈. 화면에 "복구로 간다"는 말이 없어 "차키를 또 집었다"로 보임.
   - 조치: ① 치울 물체 집기도 목표처럼 `WALL_TOO_CLOSE` 면 넛지 → 다시 보기 → 다시 집기, 잡기 실패면 다시 보기 → 다시(`_pick_retry`) ② **스킬 서버: 다른 물체 위에 얹힌 물체는 넛지가 필요해도 움직이기 전 `NOT_ON_FLOOR`** — 뒤에서 밀기 손가락이 바닥 위 3 mm 까지 내려가는데 밑 물체(이번엔 미검출 몽키) 위로 내려감, 끌기는 떨어뜨림 ③ 이미 옮겨 고정 자리에서 다시 찾은 물체의 덮음 관계는 빼고, 다음 치울 것을 못 정하면 2번까지 다시 찍기 ④ "목표를 꺼내지 못했어요 — 이유 → 옮긴 것 원위치로" 출력.
