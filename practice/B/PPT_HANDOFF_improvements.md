## 1. movesx 들고 나오기 (작업표 d14a) — [sim], 코드 없음

- **지금**: 물체를 집은 뒤 트레이까지 교시 경유점 4~5개를 `moveb`(직선 + 모서리 반지름 블렌딩)로 지남. 모서리마다 속도가 줄었다 늘었다 함.
- **아이디어**: 두산 `movesx`(작업 공간 스플라인, `opt=1` 일정 속도)로 한 번에 지나가기. 서비스 칸 확인 완료: `pos[]`, `vel[2]`, `acc[2]`, `opt`, `sync_type` (`dsr_msgs2/srv/MoveSplineTask`).
- **시뮬 결과** (`practice/B/sim/movesx_carry_sim.py`, 그림 `practice/B/img/2026-10-13_movesx_carry_sim.png`, PR #330). 두산 스플라인 식은 비공개라 3차 스플라인으로 근사:

| | 지금 moveb | 경유점 그대로 movesx | 제안: guided |
| :-- | :-- | :-- | :-- |
| 경로 모양 | 직각 + 모서리 둥글게 | 위로 **약 90 mm 부풂**, 옆으로 40 mm 벗어남, 트레이 앞 S자 | moveb 경로에서 최대 29 mm 안 |
| 길이 | 845 mm | 20~25% 길어짐 | 810 mm |
| 서랍 앞벽 여유 (TCP) | 72 mm | — | 79 mm |
| 최소 곡률 반지름 | 20 mm | — | **54 mm** (원심 가속 약 1/2.7) |

- **핵심 메시지**: "경유점을 그대로 스플라인에 넣으면 안 된다" → 스플라인은 직각 모서리 바깥으로 크게 부풂(10/06 `movesj` 로 긴 물체 들 때 경로가 벗어나 뺐던 것과 같은 위험). 그래서 **guided** = 지금 moveb 가 그리는 둥근 경로 위에서 8점을 뽑아 movesx 경유점으로, 마지막 내려가기는 movel.
- 아래 칸은 원래 굽이가 완만해서 차이 작음(흔들림 없이 이어지는 효과만).
- **남은 일**: 코드(설정 `carry.spline`, 기본 꺼짐) → PC2 저속 → 실제 TCP 경로 기록해 sim 과 겹쳐 그리기, moveb vs movesx 속도-시간 그래프.
- 슬라이드용 그림: `2026-10-13_movesx_carry_sim.png` 그대로 사용 가능.

## 2. 흐름 시간 단축 — [sim], 코드 없음

- 도구: `practice/B/sim/flow_time_sim.py` (PR #331·#332). A 의 `sim/motion_check/trace_unpack.py` 로 실물 덤프 장면에서 B 코드가 보내는 **실제 명령 목록**을 뽑고, 속도·가속 사다리꼴로 시간 계산. 그리퍼·비전 시간은 추정, 음성·Runner 처리 시간 빠짐.
- **지금 어림**: S2(판 밑 지우개) 약 **126 s**, S1(몽키 위 캐러멜·차키) 약 **170 s** (로봇 동작만).
- **가장 큰 낭비**: 탑뷰 ↔ 서랍 안 경유점 사이에서 손목(J6)이 매번 **172°** 회전, 한 번 2.5~2.9 s, S1 에서 10번. 손잡이 자세로 갈 때 J5 206° 뒤집힘.

**설정만 바꾸는 방법 (①~⑥)**

| 방법 | S2 | S1 | 위험 |
| :-- | :-- | :-- | :-- |
| ① 마지막 살포시 구간(15 mm/s) 가속만 올림 | −3% | −3% | 낮음 |
| ② 직선 가속 비율 1.0 → 1.5 | −6% | −6% | 예전 2.0 에서 "쿵쿵" → 중간값 |

| **⑥ 손목 덜 돌리기** | **−8%** | **−11%** | 카메라 간섭 확인 필요 |
| 속도 그대로 (①②④⑤⑥) | −18% | −22% | |
| 전부 | −25% | −28% | |

(④ 회전 속도 60→90 °/s 는 0~1% 라 뺌. ⑥ 은 그리퍼 180° 돌린 자세면 손목 카메라가 서랍장 쪽으로 66~95 mm 더 붙음 → 대안: 탑뷰 자세를 J6 −30° 근처로 다시 교시, 사진이 180° 돌아 A 비전 확인 필요.)

**불필요한 동작 빼기 (a~d)**

| 동작 | 지금 | 바꾸면 | S2 | S1 |
| :-- | :-- | :-- | :-- | :-- |
| a) 홈 경유 | 열고 나서·트레이 놓고·닫기 전에 홈에 들름 | 다음 자세로 바로 | −7% | −5% |
| b) 놓은 뒤 되돌리기 | 서랍 안에 놓고 경유점으로 손목 되돌린 뒤 올라감 | 올라온 자리에서 탑뷰로 바로 | −7% | −8% |
| c) 손목 왕복 | 같은 자리에서 돌렸다 되돌림 | 한 번에 | −0% | −1% |
| d) 두 번 올리기 | 트레이 놓고 두 번 연달아 올림 | 한 번 | −1% | −0% |
| **a~d 전체** | 명령 53→42개 / 73→58개 | | **−15%** | **−14%** |
| **a~d + ①②⑤** | 속도·손목 자세 그대로 | | **−24%** | **−23%** |

- **안전 판단**: b) 는 서랍 안에서 올라가기만 해서 가장 안전·효과 큼. a) 홈 경유는 10/06 실물 이유(홈→손잡이 직행 시 손잡이보다 낮게 지나감, 트레이에서 바로 올리면 팔이 펴져 제어기가 출발 안 함)가 있어 저속 실물 확인 + C(Runner 기억) 확인 필요 → **열고 나서 홈 경유는 빼지 않기로 함**.
- **1차 계획 (약 −10~12%)**: b·c·d + ①⑤. **2차**: 직선 가속 1.5, 트레이→탑뷰·닫기 전 홈 경유, 탑뷰 재교시(A 확인).

## 3. 힘 제어 넛지 `drag.force_mode` — 코드 있음(기본 꺼짐, PR #305 `7af872a`), 실물 미확인

- **문제 [실측 10/13]**: 위치 방식 넛지가 "닿았나"를 위치로 0.1 mm 씩 내려가며 찾는데, 빈 캐러멜 상자(휘어서 힘이 5 N 아래로 빠짐)·몽키 머리(윗면이 예상보다 4~5 mm 낮음)에서 `NO_OBJECT_CONTACT` 실패.
- **방법**: 두산 `task_compliance_ctrl`(z 만 부드럽게) + `set_desired_force`(아래로 목표 힘) → 제어기가 내려가 닿고 힘 유지한 채 끔(약 0.85 N, sweep 2 N) → `release_force` → `release_compliance_ctrl` → 올림.
- **안전장치**: 예상 높이보다 12 mm 더 내려가도 안 닿으면 "물체 없음"으로 풀고 멈춤, 취소·비상정지 때도 풀고, 풀기 실패면 서버 잠금, 어떤 경로로 끝나든 마지막에 한 번 더 풂.
- **sim 비교** (`practice/B/sim/force_drag_sim.py`, 1차원 접촉 모델 [sim]):

| 장면 | 위치 방식 | 힘 제어 |
| :-- | :-- | :-- |
| 지우개 | 닿음 | 닿음 |
| 몽키 머리 (윗면 4~5 mm 낮음) | 실패 | 닿음 |
| 빈 캐러멜 상자 (휨) | 실패 | 닿음 |
| 빈 칸 (물체 없음) | 실패 | 실패 (정상 거부) |

- **남은 일**: 실물 검증 순서 빈 바닥 → 지우개 → 빈 캐러멜 상자 → 몽키 머리, 끄는 동안 힘 z·위치 z 기록해 비교 그래프. 좋으면 기본값 켜기.
- 반성 포인트(발표용): "처음부터 힘 제어를 추천했어야 했다" — 일지 29번.

## 4. 지속 외력 판정 W1 `external_force` — **구현·머지 완료 (#335 `f30513a`)**, 실물 리허설 확인 중

- **실측 [10/13, `scripts/force_log.py`]**: 정지 상태 툴 힘 잡음 최대 **약 2.8 N**, 사람이 그리퍼를 손으로 밀면 **약 24 N** → 기준 **5 N · 0.5 s** (일지 32번, #326).
- **구현**: `/skills/check_state` 를 부르면 0.5 s 동안 20 Hz 로 10번 읽음. 10번 다 |F| > 5 N 이면 `true`, 하나라도 아니면 `false`, 못 읽으면 `null`. 동작 중(`busy`)이거나 **읽는 동안 로봇 상태·관절·게이트가 하나라도 바뀌면 그 창 전체를 버리고 `null`** (E #335 리뷰 반영). W2 `/skills/recover` 는 외력 있으면 `EXTERNAL_FORCE`, 모르면 `EXTERNAL_FORCE_UNKNOWN` 으로 거절.
- **원칙(발표용)**: "모름은 허가가 아니다" — 판정 못 하면 `null` 이고 C 는 `null` 을 허가로 안 봄.
- 리허설 확인 항목: 쉬는 상태 false, 손으로 밀면 true, 덮개 판 쥔 채 `external_force_n`, 응답 2 s 안.

## 6. VLM 위험 배치 감지 (작업표 d14b) — [계획], 코드 없음

- **왜**: 실패 중 규칙으로 못 푸는 건 대부분 **비전이 못 보는 상태** — 세운 물체(검출 안 됨), 기대 세운 물체(기울기 모름), 불안정하게 쌓인 것. 사진: `practice/B/img/2026-10-13_unstable_stack.jpg`, `2026-10-13_lipbalm_vertical.jpg`.
- **방법**: 탑뷰 사진 1장을 VLM(GPT-4o 등)에 물어 "세움/기댐/불안정" 을 JSON 으로 → 있으면 **움직이기 전에 거부·안내**. 학습 없음(제로샷, 필요하면 예시 사진 몇 장 퓨샷).
- **평가 계획**: 우리 사진 20~30장에 정상/세움/기댐/불안정 라벨 → 맞힌 수(재현율·오탐)로 근거.
- **검토해서 버린 것(발표에 "왜 안 했나"로 쓸 수 있음)**: "VLM 이 밀 방향을 제안하고 규칙이 검증" 은 규칙 계획만으로 sim 약 97% 성공 + 남은 실패는 공간 자체 부족이라 효과 작고, 1~5 s 지연·비결정성·인터넷 의존이 손해 → 판단 루프에는 안 넣음. YOLO-World/YOLOE 는 "무엇"만 찾고 "세웠나"는 못 봄.
- 선행: E(희태)에게 OpenAI 키 B 사용 가능 여부 확인.

## 7. (선택) 놓기만 되는 자리 → TTS 확인 → 원복 넛지 — [계획]

- 치운 물체를 둘 빈 자리가 "놓을 수는 있는데 다시 집기 어려운(벽 붙음)" 곳뿐이면 지금은 안전하게 `NO_FREE_SPACE`(꺼내지 못했어요).
- 제안 흐름: B 가 그 자리를 함께 알려 줌 → TTS "둘 수는 있는데 나중에 꺼낼 때 옮겨야 해요. 넣을까요?" → "어 넣어" → 놓기 → 원복 때 `WALL_TOO_CLOSE` 면 넛지로 끌어내 집기(C #347 원복 넛지가 이 마지막 칸).
- 계약(새 결과 칸·param)·음성 확인이라 C·E 승인 필요, 녹화 뒤.

## 8. 공통 — 안전한 도입 절차 (발표 마무리 슬라이드)

```
아이디어 → 실물 덤프로 sim (B 실제 판단 코드 그대로) → 코드 (설정 기본 꺼짐 — 지금 동작 그대로)
→ 시험·PR (E 포함 리뷰) → PC2 저속 실물 (펜던트 비상정지 손에) → 켜기
```
- 예: `drag.force_mode: false`, `carry.spline`(예정), `pick.axis_swap: true`(sim·리뷰 뒤 켬), `place.free_repickable_only: true`(C 원복 넛지 실물 확인 뒤 false 예정).
- "움직이기 전에 거부" 원칙: 판단은 전부 사전 검사로, 모르면 거부. 실패해도 쥔 채 멈추지 않게.
