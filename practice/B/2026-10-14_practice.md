### 1. 집은 뒤 경유점에서 두 번 멈췄다 한 번 더 올라감 [사용자 10/14 P2 시연 "중간 경유점이 두 개인 것 같아"]

- **원인 [코드 읽기]**: B 코드 구조. Runner 조합 문제는 아님(스킬 경계의 짧은 틈 하나뿐).
  1. `pick_object` 는 잡고 테두리 높이로 올린 뒤 **경유점 1(서랍 중앙, z 275)에서 끝나고 0.5 s 멈춤**(`carry.pause_s`, 10/06 저녁 사용자).
  2. Runner 가 다음 스킬 `place_object` 를 부름.
  3. `place_object` 는 경유점 1 에서 **J6 만 따로 돌려** 놓는 손목을 맞춤 — 짧은 1→2(64 mm)에서 65° 돌리면 제어기가 출발 안 함 [실측 10/10].
  4. 경유점 2(z 339)로 **수직 64 mm 더 올라감**(교시: 1 은 테두리 높이, 2 는 앞판 넘는 높이) → 3 → 4 → 트레이.

- **남은 것**: 1→2→3 이 한 번에 이어지는지, 2→3 에서 돌리며 제어기가 출발하는지 저속 실물 확인. 경유점 1 에서의 짧은 정지(스킬 경계)는 남음.

### 2. 서랍 안 놓기·원복에서 손목을 기본 방향으로 돌렸다가 다시 목표 각도로 [사용자 10/14 "90° 기준으로 돌려 경유점 만든 뒤 목표 각도로 — 한 번에 돌려 시간 줄이자"]
- **원인 [코드 읽기]**: 집기는 경유점 1 에 **집은 손목 그대로** 도착 → 놓기는 `drag_down` 관절(기본 손목)과 다르니 `movej(drag_down)` 로 손목을 기본으로 되돌림 → 놓는 각도로 J6 다시. 집기도 탑뷰 → `movej(drag_down)`(기본 손목) → J6 따로. 놓은 뒤엔 경유점으로 돌아가며 손목을 또 기본으로.
- **조치 (이 PR, `motion.one_turn`, 기본 false)**:
  - 이미 경유점 자리(TCP 2 mm 안)면 `movej(drag_down)` 없이 놓는 각도로 J6 한 번.
  - 다른 데서 오면(탑뷰 등) 경유점 관절 이동에 목표 J6 를 넣어 한 번에(`_down_with_turn`).
  - 놓는 손목은 지금처럼 **경유점 기본 방향 기준**으로 고름 — 지금 손목 기준이면 ± 반 바퀴가 바뀌어 손목 카메라가 벽 쪽으로 갈 수 있음.
  - 놓은 뒤 경유점으로 돌아갈 때 손목 그대로 — 다음 관절 이동(탑뷰·다음 집기)이 한 번에 돌림.
  - 끝 자세·놓는 자리는 끔/켬이 같음 [시험].
- **남은 것**: 관절 이동 중 J6 를 같이 돌릴 때 쥔 긴 물체(몽키 170 mm)가 테두리·앞판에 닿지 않는지 저속 실물 확인.

### 5. 덮개 판을 free 자리에 5 mm 위에서 놓음 — 같은 자리에 한 번은 정상 [사용자 10/14 PC2 20:11·20:15]

- **원인 [추정]**: 같은 자리에서 가끔만 → 마지막 천천히 내리기의 3 N(`place.touch_n`)을 바닥 전에 느낌. 빠르게 내려와 멈춘 뒤 힘 0점을 0.4 s(`touch_settle_s`)만 기다리고, 넓은 판을 가장자리로 잡아 툴 힘 추정(관절 토크)이 출렁인 것으로 봄. 이 멈춤은 로그가 없었음.

- **남은 것**: PC2 에서 판을 free 에 몇 번 놓아 로그로 원인 확인 → 맞으면 `touch_window_mm: 3`.

### 6. 판 치운 뒤 지우개를 안 집음 — 비전 가림 관계 '모름' [로그 `ee7344`]
- 판을 치우고 다시 찍었을 때 지우개만 `occluded_by: null`(다른 물체는 `[]`) → C `select_obstacle` 가 두 번 다 `occlusion_unknown` → 목표 집기(`s8`)까지 안 가고 "꺼내지 못했어요". B 집기·공간 만들기는 불리지 않음(B 도 null 이면 `OCCLUSION_UNKNOWN`).
- 원인(C 계산): A 지우개 기준 넓이(ref 0.001443)가 실제 윗면(52.5 × 22 = 0.001155)보다 25% 커서 다 보여도 78% → '덜 보임'(< 0.80) → null. A 기준 넓이 수정(약 0.00120) + C 좁은 예외(처음 덮던 물체를 다 옮겼고, 목표 박스가 다른 박스와 안 겹치고, yaw_valid 일 때만 가림 없음, E 동의 대기).

## 통합 환경에서 하나씩 켜며 점검 (오늘 정한 방법)
예전처럼 터미널을 따로(로봇·스킬·카메라·비전) 띄우는 건 **새 동작을 처음 만들 때**만. 시연이 된 지금은 통합 스택을 기준선으로 두고 설정을 하나씩 켬.

1. **기준선 고정**: `git pull` → `bash tools/dev/pc2_up.sh --p2` (재개 보존) + `bash tools/dev/pc2_voice.sh --p2`. `~/ready2go_pc2_logs/<시각>/ready.txt` 의 SHA·모드를 적어 둠.
2. **설정 하나만 켬**: `ros2_ws/src/ready2go_skills/params/skills.yaml` 에서 하나(`motion.one_turn` → `carry.direct` → `carry.spline` 순서) `true`. 처음 켤 땐 관절·직선 속도를 낮춰서(`.env` `SKILL_JOINT_VEL_DEG_S` 등 또는 `speed` 값), 펜던트 비상정지 손에.
3. **ros2-core 만 재시작**: `ros2_ws` 가 컨테이너에 연결돼 있어 빌드 필요 없음(yaml 만 바꿈). `bash tools/dev/pc2_cmd.sh unlock`(= `docker compose restart ros2-core`, 띄울 때 정한 `--p2` 환경 그대로) 뒤 스킬 서버 준비(`SKILL_START_DELAY_S` 15 s) 기다림. 서랍은 닫고 빈손·홈에서.
4. **같은 배치로 2~3회**: 음성 또는 `bash tools/dev/pc2_cmd.sh find <물품>`.
5. **비교**: `bash tools/dev/pc2_cmd.sh report 3` — 단계별 시간·실패 코드. 기준선 회차와 집기·놓기 단계 시간을 비교.
6. **이상하면 그 설정만 false** → 3 다시. 괜찮으면 다음 설정.
- 같이 켜지 말 것: 통합 스택이 떠 있을 때 호스트에서 `Bserver`·드라이버를 또 띄우면 스킬 서버 두 개·제어기 이중 접속.
