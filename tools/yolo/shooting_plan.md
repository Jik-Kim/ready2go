# 실물 촬영 계획표 · 점검 목록 (담당 A, #14, 일정표 Day 3 · 10/05)

촬영은 `tools/yolo/capture_session.py`로 한다(구독만 하고 로봇에는 명령을 보내지 않는다). 이 문서의 수치는 계산·추정이며, 첫 촬영 후 실제 소요 시간과 장수로 고친다.

## 1. 전제와 막힌 점

| 항목 | 상태 | 담당 |
| :--- | :--- | :--- |
| 촬영 자세 `drawer_top_view` | `config/poses.yaml`에 `null`. **A(사용자)가 직접교시로 정하고** 관절값을 B에게 넘기면 B가 등록·경로 안전 확인(PM 정리 10/04). 데이터 수집의 선행 조건은 이것 하나 | A → B |
| 서랍 인출 거리 | **최대 인출 0.225 m(스토퍼)에서만 촬영.** 서랍 좌표 `tf`가 이 거리에서만 유효하고 V2 추론도 같은 거리에서 하기 때문 | B(DRAWER_NOT_AT_TRAVEL, #15) |
| 로봇 슬롯 | 시간대 확정 필요 | A·B |
| 펜던트 TCP·tool weight | 10/04 3점 터치 때 풀려 있었음(PR #58). 촬영 전 `GripperDA_v1`·`tool_weight` 설정 확인 | B |
| 클래스 번호 | `config/yolo_classes.txt` 11종 확정(0~10). 새 클래스는 맨 끝에만 추가 | — |
| 사전 라벨링 도구 | `vision` 컨테이너에서 실행. 모델 파일이 필요하면 내려받기 승인을 따로 받는다 | A |

## 1-1. `drawer_top_view` 정하기 (오늘 로봇 순서 ①)

1. 펜던트에서 TCP `GripperDA_v1`과 tool weight 설정을 확인한다(3점 터치 때 풀려 있었음).
2. 서랍을 최대 인출(22.5 cm, 스토퍼)까지 연다.
3. 직접교시로 손목 카메라가 서랍 안을 **거의 수직**으로 보게 맞춘다. 내부 전체와 벽 4개가 화면에 들어와야 한다. 맞추면서 `/wrist_cam/color/image_raw`를 화면으로 확인한다.
4. 관절값(deg 6개)을 기록해 B에게 넘긴다. B가 `config/poses.yaml`의 `drawer_top_view`에 등록하고, 이동 경로(관절 한계, 서랍장 윗판 간섭, `home`에서 가는 경로)를 확인한다.
5. 이후 촬영은 이 자세에서 한다. 로봇 이동 명령은 사용자가 직접 실행한다.

값을 읽는 명령은 읽기 전용이다(실제 로봇의 DDS 환경은 B의 구성에 따르며, 이 문서에서는 `[미확인]`).

## 2. 세션 구성

세션은 같은 유형·조명의 촬영 묶음 하나이고, 학습/검증 분할은 세션 단위로 한다. 한 세션 안에서는 이미지마다 물품 배치를 바꾸고(같은 배치를 반복해 찍지 않는다), 검증 세션은 학습 세션에 나온 배치를 쓰지 않는다. 이미지마다 Enter로 저장한다(`--interval 0`).

| 세션 | 유형 | 이미지 수 | 설명 |
| :--- | :--- | ---: | :--- |
| `s01_single` | 단독 | 66 | 11종을 각각 혼자 놓고, 위치 3곳 × 방향 2가지(긴 변을 x축에 나란히 / 45° 기울여) |
| `s02_spread` | 분산 | 50 | 3~4개를 서로 떨어뜨려 배치. 클래스 조합을 매번 바꿈 |
| `s03_overlap` | 겹침 | 30 | 일부를 다른 물품 위·옆에 겹치게(가림 순서 `top_z` 평가용) |
| `s04_wall` | 벽 인접 | 20 | 긴 변이 옆벽·뒷벽에서 1 cm 이내(`nudge_object` 시나리오). 얇은 지우개·차 키 중심 |
| `s05_empty` | 빈 서랍 | 6 | 물품 없음(오검출 방지용 배경 이미지) |
| `s06_var_height` | 시점 변화(높이) | 20 | `drawer_top_view`에서 높이를 ±3 cm 정도 바꿔 가며 분산·겹침 배치 [추정: 폭은 첫 사진으로 조정] |
| `s07_var_angle` | 시점 변화(각도) | 20 | 카메라 기울기를 ±5° 정도 바꿔 가며 분산·겹침 배치. 포즈 재현 오차에 강해지게 한다 |
| `s90_val_a` | 검증 | 10 | 위 유형을 섞되 학습 세션에 나온 배치를 쓰지 않는다 |
| `s91_val_b` | 검증 | 10 | 위와 같음, 다른 배치 |
| **합계** | | **232** | 클래스당 약 50개 인스턴스 [계산: 단독 6 + 분산 약 16 + 겹침 약 10 + 벽 약 4 + 시점 변화 약 8 + 검증 약 6 이상] |

- 클래스당 150~300장(`docs/vision.md` V1) 목표 대비 **오늘 세트는 최소 세트**다. 부족하면 같은 유형을 새 세션(`s06_…`)으로 보충한다.
- 세션 이름에 시점을 표시한다(기준 시점은 `_v0`, 시점 변화는 `s06_var_height`·`s07_var_angle`). 검증 세션은 기준 시점으로 찍는다.
- 겹침·장애물 장면도 찍되 P1 학습·평가는 보이는 물체로 한정한다.
- 소요 시간 [추정]: 이미지당 배치 변경 약 20초 → 232장 약 80분 + 시점 변경·준비. PM 계획의 1.5~2시간 안에 들어온다. 첫 세션에서 실제 시간을 재고 조정한다.
- 조명은 시연 조건과 같은 하나로 고정한다. 조명 변화(밝기 ±)는 보충 세션에서 별도로 둔다.

## 3. 촬영 전 점검 목록

**환경**
- [ ] 조명을 시연 조건으로 고정하고 촬영 중 바꾸지 않는다(창가 햇빛 변화, 그림자 방향 포함)
- [ ] 서랍 안쪽 바닥·벽을 닦고 이물질 제거. 광택이 있으면 무광 종이로 가린다(뎁스 반사)
- [ ] 물품 11종이 모두 있고, 이슈 #8의 표와 같은 개체인지 확인(눕힌 상태 기준)
- [ ] 물품·서랍 외에 화면에 들어오는 것(손, 케이블)을 치운다

**로봇·카메라**
- [ ] 펜던트 `TCP = GripperDA_v1`, `tool_weight` 설정 확인(10/04에 풀려 있었음)
- [ ] 서랍을 최대 인출(22.5 cm, 스토퍼)까지 열고 `drawer_top_view` 자세로 이동(로봇 조작은 사용자·B)
- [ ] `realsense` 컨테이너 기동, `/wrist_cam/color/image_raw`와 `/wrist_cam/aligned_depth_to_color/image_raw`가 약 30 Hz로 오는지 확인
- [ ] 카메라 노출·화이트밸런스가 촬영 중 변하지 않게 고정 [추정: realsense 파라미터로 자동 노출 끔 — 방법은 첫 촬영 때 확인]
- [ ] 첫 이미지 2~3장을 저장해서 눈으로 확인: 서랍 안쪽 전체가 보이는지, 초점, 뎁스에 구멍이 많은지

**저장**
- [ ] `data/raw/<세션>/`에 컬러(images/)와 정렬 뎁스(depth/)가 같은 장수로 저장되는지
- [ ] `--note`에 배치 유형·조명·시간대를 적는다. `--gt-yaw-method`는 정답 yaw 기록법이 정해지면(#62) 사용
- [ ] `data/`는 저장소에 올리지 않는다(.gitignore). 촬영 후 다른 디스크에 복사

## 4. 촬영 중 규칙

- 이미지마다 배치를 바꾼다. 같은 배치를 두 번 찍지 않는다.
- 물품이 서랍 안쪽 경계(옆벽·뒷벽)에서 잘리지 않게 놓는다(벽 인접 세션 제외).
- 겹침 세션에서도 모든 물품의 윗면 일부는 보이게 한다.
- 뎁스 결손이 많은 물품(반사·검정·투명)은 따로 메모해 둔다(`DEPTH_INVALID` 임계값 조정에 쓴다).
- 세션이 끝나면 `session.yaml`의 장수와 폴더 장수를 비교한다.

## 5. 촬영 후 (사전 라벨링)

1. 사전 라벨링: `vision` 컨테이너에서 오프라인 실행 `[팀 확정 필요: 도구 — YOLO-World 등, 모델 파일 내려받기 승인 필요]`
2. 사람이 수동 보정. 클래스 id는 `config/yolo_classes.txt` 줄 번호
3. 라벨 결과를 `data/labeled/<세션>/images`, `labels`(YOLO txt)로
4. `python3 tools/yolo/build_dataset.py --val s90_val_a s91_val_b`로 데이터셋 구성(라벨 오류·id 범위 점검 포함)
5. 클래스별 인스턴스 수를 세어 부족한 클래스를 보충 세션에 반영
